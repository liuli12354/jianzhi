# 简知（JianZhi）· 需求定义（PRD）

> 版本 v0.1.0 ｜ 2026-09-13 ｜ 状态：已实现并通过验证
> 上游调研：`docs/research/`（9 个同类开源项目对比）

## 1. 背景与立项依据

对 9 个主流开源知识库/笔记项目做了系统调研（Memos、Trilium、Joplin、AFFiNE、Outline、Docmost、SiYuan、Logseq、BookStack，详见调研文档），提炼出四条关键结论：

1. **重型项目功能强但成本高**：AFFiNE/Outline/Docmost/SiYuan 功能全，但依赖 Postgres/Redis/对象存储等多件套（Outline 需要 PG+Redis+S3+OIDC），或桌面端资源占用失控（AFFiNE 社区反馈内存泄漏），上手与自托管门槛高。
2. **超轻项目缺组织能力**：Memos 零门槛（单容器+SQLite）值得学习，但无笔记本层级、无双链、无版本历史，"速记"多而"知识库"弱。
3. **中文全文搜索是长期共性痛点**：Memos 的 SQLite FTS、Joplin 的多端搜索都有社区抱怨；而个人规模数据用"子串匹配"就能把中文搜索做对。
4. **双链是知识库区别于笔记软件的差异化能力**：SiYuan/Logseq 用户的主诉求；Trilium 的"树/克隆/链接混合组织"也印证了链接的价值。

**立项**：做一个「开箱即用、单机零外部依赖、覆盖个人知识管理主线」的轻量级 Web 知识库——取 Memos 的部署哲学 + Trilium/SiYuan 的链接组织 + 对中文检索友好的朴素实现。

## 2. 目标用户与核心场景

- 目标用户：个人用户；本地或内网自托管；单用户（v0.1 不做鉴权与多用户）。
- 核心场景：**快速记录 → 归类整理（笔记本+标签）→ 检索回找（全文搜索）→ 知识关联（双链+反链）→ 误删兜底（回收站+版本历史）**。

## 3. 功能范围

### P0（v0.1 范围，全部已实现 ✅）

| 模块 | 功能 |
|---|---|
| 笔记 | Markdown 编辑（编辑/分屏/预览三种模式）、自动保存（800ms 防抖）+ Ctrl+S 立即保存、字数统计、无标题时自动取正文首行 |
| 组织 | 笔记本（创建/重命名/双击改名/删除，删除后笔记保留为"未分类"）、多标签（彩色 chip、按标签筛选、计数） |
| 检索 | 全文搜索（标题+正文子串匹配，中英文均支持、英文大小写不敏感）、Ctrl+K 全局搜索弹窗（↑↓ 选择、回车打开、关键词高亮） |
| 关联 | `[[标题]]` 双链语法（可带别名）、点击跳转（按标题解析）、反向链接面板（哪些笔记引用了当前笔记） |
| 收纳 | 收藏（star）、置顶（pin，列表内优先排序）、排序切换（更新/创建/标题） |
| 兜底 | 回收站（软删除/恢复/彻底删除/清空，回收站内笔记只读）、版本历史（标题或内容每次变更自动快照，保留最近 20 版，可一键恢复） |
| 数据 | 导入 .md/.markdown/.txt（可多选批量）、单篇导出 .md、全量导出 JSON 备份 |
| 体验 | 暗色/浅色主题（记忆偏好，跟随系统初始化）、Toast 反馈、确认弹窗（避免原生对话框）、快捷键 Ctrl+N / Ctrl+K / Ctrl+S |

### P1（v0.2 候选）

SQLite FTS5 + trigram 中文全文索引、图片粘贴与附件、笔记在笔记本间拖拽移动、定时自动备份、PWA 离线。

### P2（远期）

多设备同步（参考 Joplin 同步目标抽象层）、协作（参考 Docmost/Hocuspocus）、AI 能力。

## 4. 非目标（v0.1 明确排除）

- 多用户 / 权限 / 登录鉴权
- 实时协同编辑
- 云同步与移动端

## 5. 验收标准（全部达成 ✅）

1. 后端 API 集成测试 13 项全部通过（覆盖 CRUD、标签、搜索、版本、回收站、导入导出、404/校验）。
2. 前端 TypeScript 严格模式零错误，生产构建成功（gzip 后约 102KB）。
3. UTF-8 中文「写入→读取→搜索」回环校验通过。
4. 浏览器实测核心流程：新建笔记本 → 新建笔记 → 编辑自动保存 → 全局搜索 → 双链跳转与反链 → 回收站流转。
