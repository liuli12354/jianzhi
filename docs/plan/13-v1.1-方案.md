## 1. 关键决策

1. **优先级解析**：单条任务行内匹配（互斥，取首个出现的档位 emoji）；`priority` 数值化便于排序。chip：🔺红 / ⏫橙 / 🔼黄 / ⏬灰蓝，无标记不显示。
2. **activity 口径**：`notes.updated_at`（每次保存刷新）+ `versions.created_at`（每次内容变更）双信号 UNION 计数——比单用 updated_at 更能反映真实编辑行为（updated_at 会因置顶等元数据变更而虚增，versions 只记内容变化，二者并集后按日计数仍以「内容动作」为主）。
3. **tasks due 过滤**：`listAllTasks` 结果在路由层按 `?due=` 过滤（个人库规模，无需下推 SQL）。
4. **快捕入日记**：前端调 `POST /api/journal/today` 拿到日记（惰性创建）→ 若内容非空则追加 `\n\n` + 时间戳小节；标签解析逻辑不变（同时打在日记上会污染，v1.1 选择**追加文本保留 #标签 原样**、不额外打 tag）。

## 2. 后端

- `listAllTasks()`：priority 解析多档（`🔺|⏫|🔼|⏬` → 3/2/1/-1，缺省 0）。
- 新增 `getActivity(days)`：近 N 天（默认 182，上限 366）`{ 'YYYY-MM-DD': count }`。
- 路由：`GET /tasks?due=YYYY-MM-DD`、`GET /activity?days=`；版本 1.1.0。

## 3. 测试计划（test/v11.test.mjs）

1. 多档优先级：五档行各一 → priority 3/2/1/0/-1；无 emoji 任务不受影响。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| activity 双信号重复计数 | UNION ALL 后 SUM 同日计数（一次保存产生 1 条 note 更新 + 1 条 version = 2 次活动，可接受——编辑即活动） |
| 追加日记破坏模板结构 | 追加带时间戳二级标题 `## ⚡ 14:30`，与三段式模板兼容 |
| 热力图色阶在暗色主题对比不足 | CSS 变量按主题分别定义 5 档 |
