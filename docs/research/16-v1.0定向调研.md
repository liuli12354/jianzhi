## 一、快速捕获（形态 + 默认去向 + 反馈）

### 1.1 flomo 浮墨（flomoapp.com + help.flomoapp.com）

| 维度 | 结论 | 依据 |
|---|---|---|
| 输入框形态 | **双形态并存**：① 独立弹层——客户端全局快捷键 `⌘N / Ctrl+N`「打开 MEMO 输入框」，手机长按图标或桌面快捷小部件，Win/Mac 菜单栏常驻图标；② 内嵌——Web/客户端中 `⌘/ Ctrl+/`「激活输入框」（MEMO 列表顶部常驻一条）。输入框被专门设计为「如聊天窗口一般的输入框」，好处是「专注记录想法，无需思考标题和排版」 | help.flomoapp.com/basics/quick-input（快速记录页）；官网首页「无需格式、无需排版、无需分类」 |
| 默认去向 | 统一的**时间流**（MEMO 列表按时间倒序堆叠），没有笔记本/文件夹选择步骤——理念是「像微信聊天一样简单」，从交互上消灭「存到哪里」这个决策 | 官网首页 + 快速记录页 |
| # 标签内联 | 支持，且**写在正文任意位置**（「至于标签放在开头还是结尾，以及是否放在 MEMO 中间，这个并无标准，顺手就好」）；以**空格结束**标签，「多个标签之间记得加空格」；支持多级标签 `#标签/子标签`（如 `#Books/Different/营销近视症` 即三层）；一条 memo 可带多个标签；输入框下方有「#」按钮辅助插入；限制：标签内不要用 emoji/特殊字符，英文用连接符（`#Apple_seed`） | help.flomoapp.com 多级标签页 |
| 保存反馈 | 发布快捷键 `Shift+Enter / Ctrl+Enter`；保存后卡片直接进入时间流，像聊天消息一样向上堆叠（官方帮助页未描述专门的成功动画，「像聊天」即其反馈隐喻）；回顾靠时间线 + 「相关笔记」推荐 + 桌面小部件/微信提醒 | 快速记录页 + 官网首页 |
| 微信输入 | 关注服务号「flomoapp」→ 绑定账号 → 服务号对话框内**直接发消息即存**；支持文字、图片，表情和文件暂不支持；建议置顶服务号；微信侧无法转发收集（官方称 flomo 不提倡大量搬运） | help.flomoapp.com 微信输入页 |

### 1.2 Memos（github.com/usememos/memos + usememos.com/features）

| 维度 | 结论 | 依据 |
|---|---|---|
| 定位 | 开源自托管：「open-source, self-hosted home for short-form thinking」，口号「Fast enough for every thought. Private enough for all of them.」；「Write in Markdown, attach media, and **save without choosing a title, folder, or template**」 | GitHub README |
| 输入框形态 | 主界面顶部内嵌输入框；「Quick Capture — Fast memo creation from anywhere - capture thoughts instantly without interrupting your flow」；**Instant Save — Automatic persistence while you type**（边输入边自动持久化，连「保存」按钮都能省） | usememos.com/features |
| 默认去向 | 单一时间流 + Timeline View「Browse quick notes, logs, and ideas in the order you captured them」；隐私由可见性控制——「Keep memos private or publish only what you choose」+「Public Sharing — Share selected memos publicly with simple links」（选定 memo 生成公开链接） | GitHub README + features 页 |
| # 标签 | 「Tags — Organize your memos with flexible tagging system for quick categorization and filtering」，# 标签正文内联 | features 页 |
| 保存反馈 | Instant Save 自动保存即反馈；另有 Media Support 拖拽附件；Keyboard Shortcuts 标注 WIP；浏览器扩展 Web Clipper 可保存页面/选区/图片（Chrome/Firefox） | features 页 + README |

### 1.3 Obsidian QuickAdd 插件（chhoumann/quickadd）

- 定位：四种 choice 组合——「templates, captures, macros, and multis」。
- Capture 模式：原文「**A Capture allows you to quickly add content to predefined files**」；典型用法「add a link to the open file to your daily note under a specific section」（把内容追加进每日笔记的指定小节）。
- 触发：命令面板 / 绑定快捷键（README 演示「Imagine pressing one hotkey to automatically create a new note」）。
- 格式语法：提供类似 Obsidian 模板语法的 format syntax，如 `{{DATE}}` 插入当前日期。
- 默认去向：**预定义的目标文件**（配置时指定），适合「一键写入今日日记某标题下」的固定捕获。
- 输入形态：触发后弹出输入框（详见官方文档站 quickadd.obsidian.guide 的 CaptureChoice 页）。

### 1.4 Obsidian「Memos 系」社区插件（原版 → Thino → Rememo/Memos View）

- **原版 Obsidian-Memos**（已停更/仓库下架）：flomo 风格时间线视图，memo 实际写入 **daily notes 的指定标题下**，时间线只是日记的另一种渲染。
- **Thino**（quorafind，原 Obsidian-Memos 的付费后继）：官方描述「A quick capture plugin for Obsidian, **all data from your notes**」，聚合全库笔记做捕获与回顾。
- **Rememo**（免费社区 fork，活跃维护）：「a heavily rewritten fork of Obsidian-Memos. **All memos live inside your daily notes — plain Markdown**, readable and editable at any time」。
- **Memos View**：「A flomo-inspired memos stream plugin… turns your **daily notes (or yearly files)** into a searchable, filterable memo timeline」。
- **共识**：Obsidian 生态的快速捕获默认去向 = **日记文件**，flomo 式时间线只是聚合视图；数据永远留在纯 Markdown。

### 1.5 快速捕获横向小结

- 形态上行业收敛为两种：**全局唤起的独立弹层**（flomo ⌘N、QuickAdd 快捷键）+ **主界面顶部常驻输入条**（flomo ⌘/、Memos、原版 Obsidian-Memos）。
- 默认去向的两种哲学：**无脑进时间流**（flomo/Memos，零决策）vs **写进今日日记**（Obsidian 系，与双链/任务同文件）。
- 三家共同点：不弹模态对话框打断、支持正文 # 内联标签、保存后内容立即在时间线可见。

## 二、任务优先级（emoji 约定 + 排序规则）

### 2.1 Obsidian Tasks 插件（官方文档 docs/Getting Started/Priority.md + Queries/Sorting.md）

**精确 emoji 约定（五档，从高到低）：**

| 优先级 | emoji | 备注 |
|---|---|---|
| highest（最高） | 🔺 | v3.9.0 引入 |
| high（高） | ⏫ | |
| medium（中） | 🔼 | |
| none（无） | 无符号 | 官方原文：「If a task has no priority at all, it is considered **between low and medium** priority.」（无标记 ≈ 中低之间） |
| low（低） | 🔽 | |
| lowest（最低） | ⏬ | v3.9.0 引入 |

- **位置规则**：emoji 直接 **append 在任务描述末尾**，如 `- [ ] take out the trash 🔼`。社区亦提醒：Tasks 只识别位于描述之后的优先级 emoji。
- **输入方式**：auto-suggest 智能补全——「start typing the first few characters of `high`, `medium` or `low`, and press `<return>` to accept the suggested signifier」（打 `high`/`highest priority`/`lowest priority` 等关键词即补出对应 emoji）；或用 `Tasks: Create or edit` 命令在弹窗中选。
- **排序规则**：
  - `sort by priority`：官方注明「'low' is below 'none'」，即完整顺序为 🔺 → ⏫ → 🔼 → (none) → 🔽 → ⏬；`task.priorityNumber` 中 highest=0、lowest=5。
  - **多级排序**：每行一个 `sort by`，「The first sort has the highest priority」，后续排序在前一级内部生效。要实现「同日期内高优先在前」写 `sort by due` + `sort by priority` 两行即可。
  - **默认排序链**：`sort by status.type / sort by urgency / sort by due / sort by priority / sort by path`，且**始终追加**在用户查询之后（用户自己写的 sort 优先）。urgency 本身就是 due 与 priority 的综合评分——即官方默认已隐含「临近日期内高优先在前」。
  - 日期排序细则：无效日期最先 → 有效日期从早到晚 → **无日期排最后**。
- 配套查询：`priority is (above|below)? (lowest|low|none|medium|high|highest)` 过滤、`group by priority`、`hide priority`。

### 2.2 Todoist

- 四档 P1–P4，**数字越大优先级越低**：P1 最高（红旗）、P2 橙旗、P3 蓝旗、P4 无色，**P4 是新建任务默认值**。
- 显示载体是**旗帜（flag）图标 + 颜色**，不是 emoji。
- 快速添加时直接在任务名里输入 `p1/p2/p3/p4` 即被解析为优先级（快捷语法）。
- 排序：按优先级排序时 P1 → P2 → P3 → P4；可与日期等排序组合。

### 2.3 滴答清单 / TickTick

- 四档：**高、中、低、无优先级**；官方建议「每天优先完成『高优先级任务』」。
- 排序：清单可按日期、标题、优先级等排序；更新日志确认「按优先级排序时，支持在**各优先级区域内手动拖动**排序」——即同优先级内保留手动次序。
- 与四象限联动：任务设为「今天」+「高优先级」自动进入「紧急 & 重要」象限（Eisenhower 矩阵的规则可编辑）。
- TickTick 英文帮助同样为 High/Medium/Low/None + sort by priority。

### 2.4 优先级小结

- 三家一致的行为模式：**高优先在前**（同日期/同分区内）；Todoist 与滴答给「无优先级」作默认值，Obsidian Tasks 给「无标记」定义了明确槽位（low 与 medium 之间）。
- Markdown 任务行的既成事实标准就是 Tasks 的五档 emoji（🔺⏫🔼🔽⏬），写在行尾、空格分隔；Todoist 的 P1–P4 与滴答的高中低都只有 3–4 档，映射简单。

## 三、日历聚合（标记类型 + 日记任务共存）

### 3.1 滴答清单 / TickTick 日历视图（help.ticktick.com / help.dida365.com）

- **视图族**：月视图（月度总结复盘）、周视图（周计划）、年视图（年度完成情况）、列表视图（按天查看）、时间线视图、日程视图（串联过去已完成/当前/未来计划）。
- **聚合内容**：日历里同屏显示**任务、习惯、倒数纪念日、专注记录、订阅的外部日历**；显示选项含 Show Details（在格子里展开任务的时间/所属清单等详细属性）、Show Completed（显示已完成任务与打卡）、Show Check Items（子任务）、Show Habit、Show Focus Records。
- **格子上的标记类型**：任务以**彩色条**呈现；颜色三选一——按清单、按标签、**按优先级**（选优先级时使用固定的优先级配色）；不开详情时显示精简条目，可拖拽改期；月视图**长按日期拖动**即可创建带时间范围的任务；周视图长按/拖拽建任务、拖动任务块改时间。
- **订阅**：支持订阅外部日历，把第三方日程并入同一张日历。

### 3.2 Notion 日历数据库（notion.com/help/calendars）

- 原文：「**Calendar view displays your items based on their Date property.**」——数据库必须有 Date 属性才能建日历视图；多个日期属性时可在 Layout 里「Show calendar by」切换基准日期。
- **格子内容 = 卡片**：页面标题 + 可选属性，官方原文「You can choose which properties you want displayed on the front of the cards on your calendar – like a due date or project lead」（通过 Property visibility 控制显隐与排序）。
- **交互**：Layout →「Show calendar as」可切 Week（月/周）；Today 与左右箭头导航；按住卡片**拖拽改日期**；拖卡片左/右边缘扩展为跨多天。
- **无日期条目**：不出现在日历上（日历只展示「scheduled to take place」的条目），需要靠其他视图（表格/看板）兜底。
- 同一数据库可建多个视图来回切换，「view the same database in multiple ways」。

### 3.3 Obsidian Full Calendar 插件（davish/obsidian-full-calendar）

- 定位：「Keep your calendar in your vault!」——把 FullCalendar 嵌入 Obsidian，让日程「alongside your tasks and notes」。
- **事件即笔记**：「Each event is **stored as a separate note with special frontmatter** so you can take notes, form connections and add context to any event」——事件是带特殊 frontmatter 的 markdown 文件，可在任务、笔记、事件之间自由互链。
- **事件来源**：笔记 frontmatter、每日笔记中的事件列表、只读远程日历（ICS / CalDAV，Google/iCloud/Outlook 均可订阅）。
- 视图：月/周/日等 FullCalendar 标准视图（README 附示例截图），点击格子建事件 → 生成对应笔记。

### 3.4 Obsidian Day Planner 插件（lynchjames/obsidian-day-planner）

- 定位（现维护版）：「adds editable **calendar views and basic time-tracking**」；核心是在日记里做时间规划。
- **时间块语法**：日记中写 `- [ ] 10:00 - 10:30 Wake up` 即自动出现在时间线上；状态栏有 mini-timeline「overview the upcoming 3 hours」。
- **任务来源四类**：① daily notes（日记本身）；② **obsidian-tasks 插件**——全 vault 范围内带日期的任务（如 `⏳ 2021-08-29` 或 `[scheduled:: 2021-08-29]`，「works out of the box for all the files in the vault」）；③ 在线日历 ICS（Google/iCloud/Outlook）；④ Dataview clock 属性（时间追踪）。
- 依赖：Core「Daily Notes」或「Periodic Notes」插件——这是它「看见」日记的前提；远程任务块按来源着色。

### 3.5 「日记 + 任务到期」共存模式提炼

- **托管型**（滴答/Notion）：一切皆「带日期的对象」——任务带日期落格，无日期的不上日历（Notion）或留在清单视图；习惯/倒数/专注作为**旁挂数据源**同屏叠加；格子标记 = 彩色条（可按优先级着色）+ 详情开关。
- **Markdown 型**（Obsidian）：**日期是唯一 join 键**——日记按文件日期、任务按到期/计划日期（Tasks 的 `⏳`/due）、事件按 frontmatter 日期，聚合器（Day Planner / Full Calendar）把三者铺到同一条时间线；事件本身也降级为笔记，实现「一切皆 markdown」。
- 标记类型的行业词汇：**点/数字**（轻量计数，如月视图未展开时）、**条**（有时间的任务/事件）、**颜色**（清单/标签/**优先级**三种着色维度）——滴答的「按优先级着色」是把优先级语义直接画进日历的现成方案。

## 四、落地建议汇总（每条一句话）

1. 快速捕获做「双入口」：主界面顶部常驻输入条（Memos/flomo ⌘/ 式）+ 全局/命令唤起的独立弹层（flomo ⌘N 式），弹层关闭即回原处。
2. 捕获默认去向零决策：默认进「笔记流」并可配置为「今日日记 + 默认标签」，不强制选笔记本/文件夹（flomo 与 Obsidian-Memos 两种哲学都兼容）。
3. 正文内联 # 标签为一级语法：空格结束、支持 `#标签/子标签` 多级、输入 `#` 时弹出已有标签自动补全（flomo 规则 + Memos 体验）。
4. 保存反馈做成「卡片立即插入时间线顶部」的类聊天气泡效果，避免模态对话框和成功页（Instant Save + 聊天流隐喻）。
5. 任务优先级采用 Obsidian Tasks 五档 emoji 约定 🔺⏫🔼🔽⏬（无标记 = low 与 medium 之间），写在任务描述末尾、空格分隔。
6. 输入任务时按 `high/medium/low/highest/lowest` 关键词自动补全对应 emoji，降低记忆成本（Tasks auto-suggest 模式）。
7. 排序规则定为「先按到期日、同日内按优先级 🔺→⏫→🔼→(无)→🔽→⏬」，无日期任务永远排在最后（Tasks 的 sort by due + sort by priority 语义）。
8. UI 上同时提供 高/中/低/无 四档简化档位（Todoist/滴答习惯），内部映射到五档 emoji 枚举，重度用户可手写 emoji。
9. 色彩编码沿用行业惯例：P1 红 / P2 橙 / P3 蓝 / P4 无色，并让日历格子上任务条的颜色直接按优先级着色（滴答「按优先级着色」方案）。
10. 日历聚合以「日期」为唯一 join 键：笔记按日记日期、任务按到期日，同格混排，用**标记类型区分语义**——任务 = 彩色条、日记 = 数字/点徽标、习惯/打卡 = 圆点。
11. 日历交互底线对齐滴答/Notion：点/长按空白建任务、拖拽改期、拖边缘改时间跨度、月/周切换、Today 回位。
12. 优先级筛选之外保留「无优先级」作为有效状态（介于中低之间可参与排序），避免逼用户给所有任务标级别（Tasks 设计理念）。
13. 仿 Day Planner 增加侧栏/状态栏「未来 3 小时」迷你时间线，让日历语义在不打开日历页时也可见。
14. v1.0 不做：微信输入、ICS/CalDAV 订阅、CalDAV 写入等外部集成——先守住「Markdown 单一数据源 + 日期 join」的架构（Full Calendar 的事件即笔记模式是 v2 参考方向）。
