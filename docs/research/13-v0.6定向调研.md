## 一、未链接提及（判定口径 + 展示形态 + 一键转链）

### 1.1 分组设计（Obsidian 反链面板）
反链面板分两组：
- **Linked mentions**：其他笔记中包含指向当前笔记的 `[[内部链接]]` 的位置。
- **Unlinked mentions**：其他笔记正文中以**纯文本**形式出现当前笔记名（含别名 alias）的位置。

两组均**按笔记聚合**，每组显示笔记名 + 该笔记内的命中次数；面板顶部有总数徽标。

### 1.2 未链接提及的判定口径
- **匹配对象**：当前笔记的标题（含别名），按纯文本匹配；匹配**不区分大小写**（Obsidian 在 2020 年按社区反馈将反链匹配改为 case-insensitive，例如 "my notes" 会被算作笔记 "My Notes" 的未链接提及）。
- **不排除代码块 / URL / 链接文本**：代码块、Markdown 链接标记内的命中也会被计入——社区长期 feature request 要求排除 code block / link markup，官方至今未做；论坛反馈在命中 URL、常用词时面板"几乎不可用"。社区还提出过 per-mention 的 "ignore/dismiss" 按钮请求，官方未实现。
- **是否排除标题自身 / frontmatter**：官方文档无明确说明（正文匹配为主）。这是 Obsidian 的历史包袱，简知可以自行做得更好。

### 1.3 展示形态
- 每条 mention 默认显示**折叠的上下文片段**，有 "Show more context" 开关可展开为完整段落；提供 "Change sort order" 排序选项。
- 未链接提及每条带 **Link button（转为链接按钮）**：一键把该处纯文本替换为 `[[wikilink]]`；社区另有 "Link Unlinked Mentions" 插件支持批量转链。偶有用户反馈按钮"消失"（通常与匹配检测方式有关，如匹配发生在链接语法内部时无法转链）。
- 已链接提及中的笔记，其未链接提及仍会重复展示（社区请求隐藏该类重复，官方未实现）。

### 1.4 性能考虑
- 官方未提供忽略/排除能力，全词全文匹配 + 逐条渲染上下文在大型库中开销明显；论坛将其列为高优先级诉求（"ignore button" 被指出计算成本高）。
- 可借鉴的工程取向：匹配放服务端（数据库层全词匹配/FTS）、分页懒加载、上下文片段截断、默认限量渲染。

## 二、任务聚合（分组维度 + 回写能力 + 入口设计）

### 2.1 Obsidian Tasks 插件（事实标准方案）
- **聚合方式**：在任意笔记写 ` ```tasks ` 查询代码块，收集**整个库**的任务并在阅读/Live Preview 中渲染结果。
- **查询语法**（过滤）：`not done`、`done`、`due before tomorrow`、`happens before ...`、`tag includes project`、`path includes ...`、`heading includes ...` 等；任务识别 `- [ ]` / `* [ ]` / `1. [ ]`，支持缩进子任务但仅限单行。
- **日期字段**：created / start(🛫) / scheduled(⏳) / due(📅) / done(✅)，支持重复任务(🔁)；`group by happens` 取 start/scheduled/due 中最早者分组。
- **分组/排序**：`group by due / happens / tag / path / folder / filename / heading / priority / status / recurring` 等，任意指令可加 `reverse`（如 `group by due reverse`）；`sort by due`、`sort by description` 可组合；`explain` 指令可输出查询解析说明。
- **限量**：`limit 100`——官方警告一次渲染成百上千任务会"明显拖慢 Obsidian 编辑性能"。
- **回写能力（关键）**：官方原文 "You can toggle the task status in any view or query and it will update the source file."——**查询结果中直接勾选会写回源文件**，保证笔记是唯一数据源。
- **入口位置**：无专门侧边栏面板；入口是"查询块"，可收藏常用查询页；提供全局过滤器设置（如 `#task`）和 "Tasks: Create or edit" 编辑命令。

### 2.2 Logseq（块级任务 + 查询）
- **状态关键词**：两套命名 `TODO / DOING / DONE` 与 `LATER / NOW / DONE`，另有 WAITING / CANCELED；优先级 `[#A]/[#B]/[#C]`，支持 `SCHEDULED` / `DEADLINE`。
- **内置聚合**：内置 NOW / NEXT 查询块——NOW 显示近两天 journal 上 NOW/DOING 任务，NEXT 显示 NOW/LATER/TODO；simple query 如 `{{query (todo now)}}`、`(priority a)` 可跨全库（含 journal）检索；复杂展示用 advanced query 或 `config.edn` 的 `:query/result-transforms`（如 `:add-task-attrs` 在表格中补状态/优先级/截止日列）。
- **回写能力**：查询结果里的任务**就是块本身**，点击状态关键词原地循环切换（TODO→DOING→DONE），天然回写；社区插件可把过去 journal 的未完成任务迁移到今日。
- **入口位置**：搜索栏输入 NOW/TODO 即可列出任务；**没有原生左侧栏 Tasks 区**（长期 feature request 建议按状态/截止日期/页面分区）；惯用做法是把任务查询页用 Shift+点击固定到右栏常驻。

### 2.3 思源笔记（无内置，社区插件补位）
- **无内置全库任务面板**，主要社区方案：
  - `syh19/siyuan-plugin-task-list`：**右侧 Dock 面板**，按 **文档 / 笔记本 / 工作空间** 三个范围聚合任务，树状结构显示任务归属；顶部按钮支持刷新、全部展开/折叠、**未完成/已完成/全部三态过滤**、搜索高亮；点击任务节点跳转原文档并滚动定位高亮；过长任务文本截断、悬停看全。README 未明确面板内勾选是否回写（未确认）。
  - `Achuan-2/siyuan-plugin-task-note-management`：任务提醒、日历视图、项目管理、**四象限面板**、番茄钟、习惯打卡。
  - 也有用户用思源"数据库"自建任务面板（列表视图 + 看板视图）。
- 分组维度取向：按**归属层级**（文档/笔记本/工作空间）而非按状态/日期，状态只做过滤。

## 三、标签管理（入口 + 合并语义 + 影响提示）

### 3.1 Obsidian
- **核心能力**：标签面板支持按名称/使用频率排序、点击跳转搜索、嵌套标签 `#a/b` 树状展示；但**截至 2025 年核心版仍无原生标签重命名/合并/删除**（只有搜索，无批量替换），社区靠插件解决。
- **Tag Wrangler（事实标准）**：在标签面板**右键** → 重命名 / 搜索 / 打开标签页；**重命名会连同其所有子标签级联改名**；把标签重命名为一个**已存在的标签名即等于合并**——全库所有笔记中的旧标签被替换为新标签；删除则从全库移除。无内置影响预览。
- **Tag Group Manager（补充）**：提供**影响范围预览**（列出将被影响的子标签与重命名结果）+ 级联重命名模式，删除标签时自动清理标签组/颜色配置。
- **社区共识**：批量删除不可逆，推荐"重命名成已有标签"曲线完成合并；操作前先用搜索查看影响面。

### 3.2 Bear（标签即文件夹，最顺滑的体验）
- **入口**：侧边栏即管理入口——Mac 右键标签、iOS 长按选 "Edit Tag"。
- **重命名 = 全局改写**：改侧边栏里的标签名，Bear 会改写**每一条**包含该标签的笔记。
- **合并语义**：重命名为一个已存在的标签名 → 两个标签自动合并，笔记归入合并后的标签；这是官方认可的合并方式。
- **嵌套**：把标签重命名为 `父/子` 形式即嵌套（如 `travel` → `travel/europe`）；注意嵌套标签搜索需输入完整路径。

### 3.3 思源笔记
- **入口**：左侧 Dock 的标签面板，点击标签跳转搜索结果。
- **重命名/删除**：v1.7.3 起支持**标签面板内重命名/删除**；机制上作用于全库所有内容块（删除 = 从所有笔记中移除该标签）；后续版本优化为**后台批量处理**，不再逐条等待数据写入。
- **API 化**：3.7.0 新增 `tag` API（列出标签、改名、删除），供脚本/插件批量管理。
- **已知坑**：标签中含特殊符号会导致无法全局搜索、且面板中无法重命名/删除——提示用户命名规范很重要。

### 3.4 共性结论
- 入口：三家（含插件）都把管理入口放在**标签面板的右键/编辑菜单**，而非设置页。
- 合并语义统一为：**重命名到已有标签名 = 合并**。
- 成熟做法 = **先展示影响预览（受影响笔记数/列表）→ 确认 → 全局改写**；删除比合并危险，需要更强的二次确认与不可逆提示。

## 四、落地建议汇总（每条一句话）

1. 反链面板按「已链接提及 / 未链接提及」两组展示，均按笔记聚合并显示命中计数。
2. 未链接提及判定口径取「标题+别名、全词、大小写不敏感」，但**排除代码块与 frontmatter**——Obsidian 不排除是历史包袱，简知应直接做对。
3. 每条未链接提及显示折叠的上下文片段，并提供「一键转链」按钮（把该处纯文本替换为 `[[标题]]`），转链后立即从列表消失。
4. 支持忽略单条未链接提及（持久记录忽略位置），并默认隐藏已出现在"已链接提及"中的笔记，减少噪声。
5. 未链接提及匹配放服务端 SQLite（FTS/全词匹配）分页返回，前端懒加载限量渲染，避免大库卡顿。
6. 任务聚合做独立侧边栏面板，分组维度提供「按状态 / 按截止日期 / 按笔记」三种，支持组折叠与计数。
7. 聚合视图中勾选任务必须**回写源笔记**（对齐 Tasks 插件 "toggle updates the source file" 的承诺），保持单一数据源。
8. 过滤能力覆盖状态/标签/日期区间/所在笔记，渲染设上限（如 limit 100），并提供筛选条件回显（对齐 explain）。
9. 任务面板内点击任务跳转原文并滚动高亮（对齐思源插件），另支持在笔记内嵌任务查询块作为进阶入口。
10. 标签管理入口放标签面板的右键/更多菜单：重命名、合并、删除。
11. 重命名级联作用于子标签（对齐 Tag Wrangler / Bear）；重命名到已有标签名即合并，弹窗写明"两标签的 N 条笔记将合并"。
12. 所有标签批量操作前先展示受影响笔记数与预览列表；删除操作二次确认并明确"不可逆"，同时约束标签命名禁用特殊字符。
