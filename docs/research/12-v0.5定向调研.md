## 一、笔记拖拽移动（各产品做法 + 简知建议交互要点）

### 1. Obsidian（文件面板拖动文件换文件夹）

官方帮助《File explorer》（help.obsidian.md → obsidian.md/help/Plugins/File+explorer，经 GitHub `obsidianmd/obsidian-help` 仓库原文核实）：

- 定位：File explorer 是核心插件，明确列出 "Move files and folders with drag and drop"（用拖拽移动文件与文件夹）。
- 拖拽语义：**"Drag a file or folder to the folder you want to move it to."** —— 文件面板内拖放的目标只有「文件夹」一种，放到文件夹上即移入其中；面板内不支持拖到两个文件之间手动排序（排序由 sort order 规则决定；社区插件 Drag and Drop Sort 才补充了"蓝色放置指示线 + 手动排序"）。
- 多选拖拽：**Alt-Click**（Windows/Linux）/ **Opt-Click**（macOS）逐个多选离散文件，连续区间用 **Shift-Click**，然后整体拖到目标文件夹。
- 另一个容易混淆的行为（官方 tip 原文）："You can drag a file from the File explorer into your note to create a link to it" —— 从文件面板拖进**编辑器**是生成链接/嵌入，不是移动。即"拖到文件夹上=移动、拖到编辑器=引用"，两种目标语义被明确区分。
- 备选移动入口：右键 → **Move file to...** → 模糊搜索文件夹名并选择（键盘可达，等价于命令面板风格）。
- 高亮形态：官方文档未描述放置高亮细节。实际交互中（论坛与主题开发资料佐证）悬停的文件夹行会出现高亮/描边以示可放置；若要像素级复刻需查其 CSS 类（如 `is-being-dragged` 等），非官方承诺行为，仅供参考。
- 移动后反馈：无移动成功 toast，也无专门的移动撤销；链接一致性由设置 **Settings → Files and links → Automatically update internal links** 保障（原文："When enabled, Obsidian automatically updates internal links when you rename a file. Turn this off to be prompted to update links after renaming." —— 重命名场景官方明示，移动同理自动改链；关闭后改为弹出确认提示）。

### 2. Notion（页面拖到父页面 / 侧栏）

官方帮助《Navigate with the sidebar》（notion.com/help/navigate-with-the-sidebar 及中文版）：

- 嵌套（变子页面）：**"Nest pages by dragging one into another. You'll see the selected page highlight blue."** —— 拖 A 页面到 B 页面上，B（及被拖项）出现**蓝色高亮**，松手后 A 成为 B 的子页面。
- 解除嵌套：可以把子页面**拖出**其父页面的折叠列表，回到上层。
- 排序：拖到两个页面**之间**的空隙 = 调整同层顺序（与"拖到页面上面=嵌套"是两种不同目标区）；侧栏分区（Teamspaces / Shared / Private）标题也可拖动重排。
- 权限警示：把页面从共享区拖进 Private 时官方明确提示 "others will lose access"（他人将失去访问权）——破坏性/有副作用的放置目标会给警告。
- 附带目标：把页面拖到 Trash 上 = 删除（默认进回收站 30 天）。
- 移动后 toast/撤销：帮助文档未提及移动成功提示；Notion 实际使用中会出现带 Undo 的浮动条，但属未见于官方文档的通用行为，简知不宜把它当作"官方约定"。

### 3. SiYuan（文档树拖拽）

- 文档树支持拖拽移动文档；多选：**Ctrl+Click** 多选后可拖拽批量移动/排序（官方仓库 Issue #1359 "文档树支持 Ctrl+Click 和 Shift+↑/↓ 进行多选" 记录了该需求与落地）；Shift+Click 的语义曾是"在下方打开文档"而非多选（Issue #12185 继续讨论辅助键行为）。
- 官方用户指南《快捷键》文档（`siyuan-note/siyuan` 仓库 app/guide 用户指南原文）中"点击/拖拽时使用辅助键"一节列出 **Ctrl拖拽 / Alt拖拽 / Shift拖拽** 等组合，说明树内拖拽与辅助键组合是正式能力。
- 移动端：3.7.0 起支持拖拽文档树、文档标签、块标等（官方更新一览，第三方整理见知乎《思源笔记 3.7.0 超大杯更新一览》）。
- 块级拖拽：块图标（⌫/⋮ 句柄）可拖拽，支持文档内与**跨文档**移动（v1.5.3 官方公告"支持多选块拖拽移动"）。
- 目标区分（拖到文档上 vs 文档之间）：通行行为是**拖到目标文档中部=移动为其子文档、拖到两行之间=插入该位置**（与 Notion 同构）；此细节为社区教程综合描述，官方指南未逐字明示，采纳时保留验证余地。
- 移动后反馈与找回：官方文档未描述移动 toast；思源提供《数据历史》功能（用户指南独立章节）可回溯文档移动/删除历史，属于"事后找回"而非"即时撤销"路线。

### 4. 简知建议交互要点（v0.5）

- 源状态：拖起时被拖项半透明 + 跟随幽灵元素；支持 Ctrl/Shift 多选后整组拖动，幽灵上显示「移动 N 篇」徽标。
- 目标双语义（对齐 Notion/SiYuan）：悬停**笔记本行中部** = 移入该笔记本（行高亮描边）；悬停**两行间隙** = 蓝色细线指示插入位。若 v0.5 手动排序未实现，先只开放"移入"并禁用间隙目标。
- 拖到普通笔记行上 = 光标显示"禁止"，松手不动作（避免 Obsidian/Notion 中"变成子文档"这类简知没有的语义）。
- 放置成功：toast「已移动 N 篇至 <笔记本名>」+ **撤销**按钮（撤销 = 回写原 parent，10 秒内有效）；批量移动失败回滚整批。
- 链接一致性：移动后自动重写所有反链/内链（对应 Obsidian 的 Automatically update internal links，默认开）；关闭该设置时改为二次确认弹窗。
- 键盘/右键等价入口：右键「移动到…」模糊搜索笔记本（对齐 Obsidian Move file to...）。

## 二、随机漫游（对标设计 + 建议范围与入口）

### 1. SiYuan「随机漫游」（集市插件「文档漫游」，terwer/siyuan-plugin-random-doc）

非内置功能，来自集市插件（README 原文核实）：

- 口号："文档就像一盒巧克力，你永远不知道下一个打开的是什么。"
- 入口：**快捷键「快速漫游」Alt+Ctrl+M**（Win）/ Alt+Command+M（Mac）；另支持顶栏插件按钮入口、**新窗口编辑**。
- 范围限定：v1.1.0 起提供**笔记本选择**；v1.5.0 新增**筛选模式，支持笔记本和根文档**两级范围；v1.4.0 支持自定义 SQL 圈定范围（高级用法）。
- 漫游历史/续跑：v1.1.0 新增 **「继续漫游」**（中断后可从上一次位置继续，说明内部保存了漫游进度记录）。
- 增值设计：v1.5.0 复习模式支持「一遍过」和「艾宾浩斯」（记得 Alt+Ctrl+R / 忘记 Alt+Ctrl+F），并有**数据面板**统计漫游/复习量 —— 把"随机打开"升级成"随机回顾闭环"。
- 相关替代：另一集市插件「漫游模式·增量阅读」（ebAobS/roaming-mode-incremental-reading）；社区还有挂件 + SQL `ORDER BY RANDOM()` 的轻量做法（说明底层就是随机查询，无黑科技）。

### 2. Obsidian「Random note」类社区插件

Obsidian 无内置随机笔记命令（论坛帖 "Random Note, excluding note types" 证实 core 缺失且用户诉求是"排除日记"）。代表性插件：

- **Ergodic**（rberenguel/obsidian-ergodic-plugin，README 原文核实）：
  - 三模式：单次跳转（命令面板 `Ergodic: Open random note (no timer)`，默认快捷键 **Alt+R**）；Leisure Walk 定时慢速漫步（侧栏 shuffle 图标启动）；Fast Walk 快速漫步（fast-forward 图标）。
  - 范围限定：**按文件夹路径或标签排除**（"you can exclude notes based on their folder path or tags"）。
  - 状态反馈：漫游中侧栏图标 shuffle/fast-forward → **pause**，状态栏同步显示；顶部可显示动画计时条。
  - 历史：移动端定时漫步时左右滑动可在随机序列中前进/**回退到历史上一条**（插件保存漫游历史栈）；停止方式多样（点 pause / 点内容区 / 按任意键）。
- **Improved Random Note Pro / Advanced Random Note** 等同类：排除文件夹（模板、归档）、侧栏 ribbon 按钮、在指定文件夹内随机、预设（presets）等——共性是"排除规则 + ribbon 入口 + 可选范围内随机"。

### 3. 简知建议范围与入口（v0.5）

- 入口三件套：侧栏「随机漫游」shuffle 图标按钮 + 命令面板命令「随机漫游：打开随机笔记」+ 快捷键 Alt+R（可在设置改）。
- 范围：默认全库；提供**排除规则**= 笔记本黑名单 + 标签黑名单（典型排除：日记、模板、归档），不做 SQL 级自定义。
- 历史：记录最近漫游序列（最近 50 条），提供「上一条（回退）/ 继续漫游」；暂不做定时漫步与艾宾浩斯复习，数据面板延后到 v0.6+。
- 反馈：跳转后短暂 toast 显示"来自随机漫游"，方便与手动打开区分。

## 三、命令面板 MRU（规则细节 + 建议实现要点）

### 1. VS Code Ctrl+Shift+P（官方文档 + 源码双重核实）

- 设置项（`workbench.contribution.ts` 原文）：**`workbench.commandPalette.history`** —— "Controls the number of recently used commands to keep in history for the command palette. Set to 0 to disable command history."，**默认 50，最小 0**（0 = 完全关闭 MRU）。另有 `workbench.commandPalette.preserveInput`：是否记住上次输入内容。
- 数据结构与持久化（`commandsQuickAccess.ts` / `CommandsHistory` 源码）：LRU 缓存，容量即 history 设置值；每次执行命令 `push` 并自增计数器；存储键 `commandPalette.mru.cache` / `commandPalette.mru.counter`，作用于 **PROFILE 作用域（按用户配置档跨会话持久化）**；采用懒保存（"only save on shutdown"），退出时落盘。
- 排序与分组（比较器源码，注释即原文）：
  - 有 MRU 记录的命令按**最近使用时间倒序**排最前（"use more recently used command before older"）；首条命中历史时插入 **"recently used" 分隔符**。
  - 用过 > 没用过（"first command was used, so it wins over the non used one"）。
  - 均没用过时按**名称字母序**（"both commands were never used, so we sort by name"），Developer 类命令垫底。
  - tf-idf 推荐命令归入 **"similar commands"** 分组并**排到底部**；内置"常用命令"归入 **"commonly used"** 分组。
  - 重要：**搜索过滤并不压制 MRU** —— 过滤后仍先按"是否用过/新旧"排序，再回退到名称序；即 MRU 优先于模糊匹配的短名优势。
- 清理：提供命令 **Clear Command History**（带确认对话框）；无"删除单条历史"能力（GitHub issue 曾有请求）。

### 2. Obsidian 命令面板（官方帮助《Command palette》原文）

- 自 **1.8.3** 起：**"recently used commands appear at the top of the Command palette. However, these recently used commands are still subject to the fuzzy matching algorithm. When you start filtering, shorter commands will be prioritized over recently used ones."** —— 空输入时最近使用置顶；**一旦开始过滤，模糊匹配得分（短名）优先于使用新旧**。与 VS Code 的策略正好相反，是两种成熟范式的分野。
- 另有 **Pinned commands**（设置中手动固定命令，永远置顶）+ 快捷键提示；MRU 数量上限与持久化机制官方未公开。
- 社区插件 Better Command Palette 曾以"最近使用 + 隐藏命令 + 文件搜索"补足旧版，1.8.3 后原生覆盖 MRU。

### 3. 简知建议实现要点

- 数据结构：LRU（上限 **50**，可配置，0 关闭），每命令记录 lastUsed 时间戳；持久化到本地（localStorage/用户配置文件），**跨会话保留**；退出或变更时惰性落盘即可。
- 空输入打开面板：顶部「最近使用」分组（MRU 序，最多展示 ~8 条 + 分隔线），其余命令按名称序。
- 输入过滤：建议采用 **VS Code 范式**——匹配分相同时 MRU 新者靠前、没用过的按名称；即"分数为主、MRU 打平"。（如更看重 Obsidian 手感，可改为"短名优先于 MRU"，二选一，不要混用。）
- 提供「清除命令历史」设置/命令（带确认）；面板内展示命令对应的快捷键（对齐两家共同做法）。

## 四、反链上下文展开（对标形态 + 建议粒度）

### 1. Obsidian 反链面板（官方帮助《Backlinks》原文核实）

面板提供四个控件，原文如下：

- **Show more context**："toggles whether to truncate or display the full paragraph that contains the mention." —— 上下文展开形态是**完整段落**（整个 containing paragraph），**不是固定 N 行**；该开关是**面板级全局两态**（截断摘要 ↔ 整段），作用于全部提及，不存在"固定展开 3 行"这类中间档。
- **Collapse results**："toggles whether to expand each note to display the mentions in it." —— 展开的最小单元是**笔记**（每条来源笔记一个可折叠组，可整体切换也可点单条组头展开/收起），不存在"逐条 mention 单独展开上下文"的粒度。
- 其余：Change sort order（提及排序）、Show search filter（按搜索语法过滤提及）。
- 附带：Unlinked mentions（未链接提及）受 Excluded files 排除规则影响。

结论（对标形态）：Obsidian 的粒度设计 = **2 档全局上下文密度（截断/整段） × 笔记级展开层级**，刻意没有做"逐条展开上下文"，控制复杂度。

### 2. 简知建议粒度

- 默认：每条反链显示截断摘要（命中词前后约 1–2 行，关键词高亮）。
- 全局面板开关「显示更多上下文」：截断 ↔ **完整段落**（与 Obsidian 完全对齐；不做固定 N 行）。
- 展开层级：按**来源笔记**分组，组头点击展开/收起该笔记的全部反链；提供「全部展开 / 全部收起」按钮（对齐 Collapse results）。
- 不做逐条 mention 的独立上下文开关（保持与 Obsidian 同样的克制）；可加搜索过滤输入框作为后续增强。

## 五、落地建议汇总（每条一句话）

1. 拖拽移动：悬停笔记本行=移入（行高亮）、行间隙=排序线（未做排序则禁用），拖到普通笔记上=禁止，多选 Ctrl/Shift 整组拖动。
2. 移动反馈：放置后 toast「已移动 N 篇至 X」+ 10 秒撤销按钮，链接/反链自动重写（设置可关，关闭时改二次确认）。
3. 移动备选入口：右键「移动到…」模糊搜索笔记本，保证键盘可达性（对齐 Obsidian Move file to...）。
4. 随机漫游入口：侧栏 shuffle 按钮 + 命令面板命令 + Alt+R 三入口，跳转后 toast 标注"来自随机漫游"。
5. 随机范围：默认全库 + 笔记本/标签黑名单（排除日记、模板、归档），历史序列保留 50 条支持回退与继续漫游，定时漫步留到后续版本。
6. MRU 存储：LRU 上限 50（0 可关）、按用户跨会话持久化、退出时落盘，提供清除历史命令。
7. MRU 排序：空输入显示「最近使用」分组；过滤时匹配分为主、同分按最近使用靠前（VS Code 范式，勿与 Obsidian 的"短名优先"混用）。
8. 反链上下文：默认截断摘要，面板级「显示更多上下文」切换为完整段落，按笔记分组展开并提供全部展开/收起，不做逐条开关。
