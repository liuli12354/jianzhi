## 一、层级笔记本树（各项目做法 + 推荐方案 + 拖拽交互要点）

### 1.1 Trilium（zadam/trilium，已迁移至 TriliumNext/Trilium）：内容与树结构分离的「边表」模型

说明：zadam/trilium 已归档/迁移，现由 TriliumNext/Trilium 以 monorepo（`apps/server` + `packages/`）方式继续开发，本节核对的源码为 `apps/server/src/services/branches.ts`。

- **数据模型**：`notes` 表只存笔记本体（noteId、title、type、content 等）；**树结构完全放在 `branches` 表**，每行表示一条 `parentNoteId → noteId` 的父子「边」，核心字段：
  - `branchId`：分支（挂载点）唯一标识；
  - `noteId` / `parentNoteId`：父子关系；
  - `notePosition`：同一父节点下兄弟排序号（**步长 10**，新分支取 `MAX(notePosition)+10`，给中途插入留空间）；
  - `prefix`：仅属于该挂载点的标题前缀（clone 时可不同）；
  - `isExpanded`：树节点展开状态，**挂在 branch 上**（同一笔记在不同父节点下展开状态可不同）；移动分支后被置 true 以便立即看到新位置；
  - `isDeleted`：软删除标记，一切查询过滤 `isDeleted = 0`。
- **Clone（一个笔记挂多个父节点）**：同一 `noteId` 对应多条 branch 记录即可在树中多处出现，每处有独立的 `branchId / notePosition / isExpanded / prefix`，内容仍只有一份。
- **移动的实现**非常能说明模型：`createClone(targetParent, newPos)` 先在目标父节点下建新分支，再把原分支 `markAsDeleted()` 软删除——「移动 = 克隆分支 + 删除原分支」，笔记本体不动。移动前用 `validateParentChild` 校验合法性（防环，如不能把父挂到自己子树里）。
- **删除**：软删除 branch；删除父节点时子树递归标记，配合 Trilium 的回收站/清空机制，可恢复。
- 子树聚合：按 parentNoteId 递归取 branch 集合即可（SQL 层即递归 CTE），无需路径字段。

### 1.2 思源笔记（siyuan-note/siyuan）：文件系统即树

- 笔记本 = 工作空间 `data/` 下的文件夹；**每个文档是一个 `.sy` JSON 文件，文件名即文档块 ID**（形如 `20230106105803-abcdefg.sy`）。
- **目录层级即文档树层级**：文档挂在哪个子目录，就出现在文档树的哪个位置；`.sy` 文件内部的 JSON 则维护块级树（`id / parentID / rootID / type / children`，文档根块 `rootID == 自身 ID`），另有 `HPath` 存人类可读路径。内核 `kernel/model/tree.go` 的加载/重置逻辑证实：树的定位靠 `Box`（笔记本）+ `Path`（文件路径），根块 `tree.Root.ID = tree.ID`。
- 优点：所见即所得、便于 Git/快照同步；缺点：移动文档 = 改文件路径，需同步重写受影响子树的路径；**不支持 clone**（一个文档只属于一个父文档）。

### 1.3 BookStack：固定三层 Books → Chapters → Pages

- 内容模型为**写死的三个层级**：Book 含 Chapter 与直接挂 Book 的 Page，Chapter 内只能放 Page，**Chapter 不可嵌套、Page 不可再有子级**。另有 Bookshelves 用于把多本 Book 聚组（不算内容层级）。
- 优点：模型极简、UI 与权限都好做；缺点：表达力弱，层级深度不可扩展。
- 删除走**回收站**（recycle bin），删除 Book 会级联其下 Chapter/Page，但可从回收站恢复。

### 1.4 数据模型选型对比

| 方案 | 代表 | 层级表达 | 子树查询 | clone | 复杂度 |
|---|---|---|---|---|---|
| 父指针邻接表 + position | 简知现状外推 | parent_id | 递归 CTE | 不支持 | 低 |
| 边表（branch 表） | Trilium | 独立 branches 表 | 同上 | 原生支持 | 中（移动/校验逻辑多） |
| 路径枚举 materialized path | 思源（文件路径） | 存路径字符串/目录 | 前缀 LIKE | 不支持 | 低，但移动要重写路径 |
| 固定层级多表 | BookStack | books/chapters/pages 各一张表 | JOIN | 不支持 | 低，表达力差 |
| Closure table | 少见于笔记类 | 全部祖先后代关系表 | 直接查 | 可支持 | 写放大，维护复杂 |

### 1.5 简知推荐方案

- **沿用邻接表**：`notebooks` 表加 `parent_id`（NULL 为根）与 `position`（步长 10，兄弟间插入直接改 2 个值），笔记表加 `notebook_id` 指到叶子笔记本；不引入 clone（个人知识库需求弱，Trilium 复杂度主要来自 clone）。
- **子树聚合**：SQLite 递归 CTE（`WITH RECURSIVE`）展开子树，选中父笔记本时聚合其下全部笔记（列表页按笔记本过滤条件改为 `notebook_id IN (子树)`）。
- **删除策略**：删除有子节点的父节点时默认**禁止并提示**，或提供「连带删除整个子树」二次确认 + 软删除/可从备份恢复；不建议静默上提子节点（三种开源项目均不这么做：Trilium 软删递归、BookStack 进回收站、思源移入历史）。

### 1.6 拖拽排序交互要点（VS Code / MUI X / dnd-kit 等成熟范式）

- **三区判定**：按鼠标在目标行内的纵向位置分「上沿（插到前面）/ 下沿（插到后面）/ 中间（放进里面当子级）」——前后用水平插入线指示，放入用节点高亮/描边指示（MUI X Tree View 设计评审、Oracle ADF 文档均为此范式）。
- **悬停自动展开**：拖到折叠节点上停留约 **300–500ms** 后自动展开（hover-intent 延迟，避免路过误展开），可配置。
- **防环**：禁止把节点拖进自己或自己的子树（Trilium 的 `validateParentChild` 同款逻辑）。
- **拖起预览**：拖动时显示笔记标题的半透明 drag image；非法目标区域显示禁止光标。
- **键盘可达性**：WAI-ARIA Tree View 模式为基础；可参考 react-sortable-tree 的键盘 DnD——Space 拾起、↑↓ 选落点、←→ 减深/加深、Esc 取消。
- **落库**：drop 只产生一次写操作——更新被拖节点的 `parent_id` + `position`（必要时更新插入点前后两个兄弟的 position），乐观更新 UI。

## 二、命令面板（交互范式 + 动作注册推荐模式）

### 2.1 Obsidian 命令面板（官方帮助文档，核对自 obsidianmd/obsidian-help 仓库源文件）

- `Ctrl/Cmd+P` 打开，也可点左侧 Ribbon 图标；打开后**输入即模糊过滤**，文档明确示例：输入 "scf" 能匹配到 "Save current file"（子序列模糊匹配）。
- **未输入时最近使用命令置顶**（1.8.3+）；开始输入后按匹配度排序，且**短名称命令优先于最近使用**。
- 列表项展示每个命令的**快捷键**，起到「边查边学」作用。
- **固定命令（pinned）**：在插件选项里添加，固定项无需输入即出现在顶部；方向键导航 + Enter 执行。

### 2.2 VS Code Ctrl+Shift+P / Quick Pick 范式

- `Ctrl+Shift+P` 执行命令、`Ctrl+P` 打开文件——**同一个 Quick Pick 控件承载两类内容**，文件模式下输入 `>` 即切换到命令模式（这是「动作与文件跳转混合编排」的经典解法：**前缀路由**）。
- 输入实时过滤，模糊匹配 + 高亮命中字符；列表项旁标注快捷键；`?` 输入可查看当前可用项的说明；`Ctrl+Enter` 在侧边打开文件；`↑/↓` 导航、`Enter` 执行、`Esc` 关闭；`Ctrl+Tab` 按最近打开循环。

### 2.3 动作与笔记跳转的混合编排：推荐模式

- **统一面板 + 模式前缀**（学 VS Code）：
  - 默认（无前缀）：同时搜「命令」与「笔记标题」（笔记结果来自已有的 FTS5 title 索引或独立 LIKE 查询），分组展示：命中笔记在上（跳转类）、命令在下；
  - `>` 只搜命令，`[[` 或 `#` 只搜笔记/标签（简知已有标签体系）；
  - 输入为空时：显示 MRU（最近命令）+ 固定项 + 最近编辑笔记。
- **动作注册用中心注册表**（Obsidian 插件体系与 VS Code `commands.registerCommand` 的共同抽象）：
  ```ts
  registerCommand({
    id: 'note.new-daily', title: '新建每日笔记',
    keywords: ['daily', '日记'],      // 提升模糊命中率
    group: '笔记', hotkey: 'Alt+D',   // 面板内展示快捷键
    when: () => true,                 // 可选：上下文可见性
    run: (ctx) => { /* ... */ }
  });
  ```
  面板是注册表的纯消费者；插件/新功能只需注册，不改面板代码。
- **模糊匹配策略**（命令量 < 数百条，无需索引）：子序列匹配 + 评分——连续命中加分、词首/驼峰/分隔符后命中加分、越靠前加分、命令越短分越高；命中片段高亮显示。
- **键盘闭环**：`Ctrl+P` 唤起 → 输入过滤 → `↑/↓` 选择 → `Enter` 执行 → `Esc` 关闭；选中笔记类结果时可 `Tab`/`Ctrl+Enter` 预览而不关闭面板（对齐 VS Code 侧开）。

## 三、Markdown ZIP 导出（目录组织 + store ZIP 实现要点）

### 3.1 各项目导出做法

**Joplin**（核对源码 `packages/lib/services/interop/InteropService_Exporter_Md.ts`）：
- **笔记本 = 文件夹**：`makeDirPath_(item)` 沿 `parent_id` 向上逐层回溯拼接 `父笔记本/子笔记本/` 相对路径；导出前预扫描一遍，对清洗后重名的兄弟笔记本用 `findUniqueFilename` 生成唯一名（存 `folderPaths_` Map）。
- **资源统一放根目录 `_resources/`**：所有附件复制进去（重名同样去重），笔记内的资源链接改写为 `${相对到根的路径}_resources/文件名`（如 `../../_resources/img.png`）。
- **两阶段导出**：先扫描全部笔记生成 `context.notePaths`（id → 最终相对路径）与 `destResourcePaths`，再逐笔记写出时把 Joplin 内部链接 `:/{id}` 全局替换为相对路径——保证跨笔记双链在导出后仍可点击。
- 文件名一律经 `safeFilename / friendlySafeFilename` 清洗非法字符。

**思源**：支持导出「文件夹的标准 Markdown」；导出单个文档时把引用的 assets 附件复制到导出目录旁的 `assets/` 文件夹；本地 `data/` 本身就是「笔记本文件夹 + .sy + assets」结构。快捷键 `Alt+Shift+B` 复制文档为标准 Markdown。

**BookStack**（官方 export-import 文档）：Page/Chapter/Book 三级都支持导出 **HTML（单文件、图片尽量内嵌）/ PDF / 纯文本 / Markdown / Portable ZIP**；ZIP 含数据 + 附件 + 图片，且有独立的 `portable-zip-file-format.md` 格式说明，可从 `/import` 回导入并支持导入前预览。Markdown 导出：原本用 MD 编辑器写的内容导出原文，否则尽力转换（部分内容仍会残留 HTML）。

**目录组织结论**：主流两条路线——① Joplin 式「按笔记本层级分文件夹 + 根级 `_resources/` 统一附件」；② 思源式「每层跟随 assets/」。**简知推荐 Joplin 式**：改写逻辑只有一套（算清每个笔记到根的相对深度即可），且附件集中便于检查。

### 3.2 无压缩 ZIP（store）实现要点

以下按 PKWARE/经典 ZIP 规范核对（local file header 签名 `PK\x03\x04`，central directory `PK\x01\x02`，EOCD `PK\x05\x06`）：

1. **三段结构缺一不可**：每个文件的 local file header + 文件数据 → 末尾 central directory（每文件一条，记录 external attributes、**local header 偏移**等）→ EOCD（本盘/总条目数、**CD 大小、CD 起始偏移**、注释长度）。EOCD 的条目数与 CD 偏移算错是手写 ZIP 最常见死因。
2. **store 方法**：local header 与 central directory 的 compression method 都写 `0`，此时 compressed size = uncompressed size = 文件真实字节数。
3. **CRC32**：对**未压缩的原始数据**计算，IEEE 802.3 反射算法（多项式 `0xEDB88320`，初值 `0xFFFFFFFF`，结果异或 `0xFFFFFFFF`，即查表法），小端写入。先算好 CRC 再写 local header，**不要用 data descriptor（bit 3）**——那要求写完数据再回填/追加 CRC，且部分解压器兼容性差；个人知识库体量（单文件几 MB）完全可以先读入内存或临时文件。
4. **中文文件名 UTF-8 标志**：General purpose bit flag 的 **bit 11（0x0800，EFS）必须置位**，且 local header 与 central directory **都要置**；文件名以 UTF-8 编码写入。**不置位时**，规范默认文件名按 IBM CP437 解释，Windows 自带解压与其他老工具会把中文文件名解成乱码。路径分隔符一律用正斜杠 `/`。
5. **目录条目**：规范上可选（解压器可凭路径前缀推断），但**建议显式写入**：名称以 `/` 结尾、大小 0、store、CRC=0、version needed ≥ 2.0——空文件夹只有靠显式条目才能保留，且对部分解压工具/Windows 资源管理器历史行为兼容性更好。
6. **DOS 时间戳**：local header 的 last mod time/date 用 MS-DOS 格式（本地时间、秒精度为 2 秒步进、年份自 1980），别写 0 以免解压出 1980 年文件。
7. **ZIP64 不需要**：< 4GB 且 < 65535 个文件即可全用 32 位字段（个人库远达不到）；超限才需 ZIP64 extra field。
8. **Node 侧落地**：`yazl` 支持显式 `store: true` 并要求调用方提供 size/CRC（语义清晰、可控 UTF-8 标志）；`archiver` 可 `zlib: { level: 0 }`；自手写约 150 行也不难，但要严格按上面 1–6 检查。导出流程照抄 Joplin 两阶段：先扫描生成「id → 目标路径」映射，再逐笔记写出并改写 `[[双链]]` 为相对路径、图片链接指向 `_resources/`。

## 四、反向链接上下文（对标做法 + 建议交互）

### 4.1 对标做法

**Obsidian**（核对官方帮助仓库 `en/Plugins/Backlinks.md`）：
- 反链面板分两段：**Linked mentions（有 `[[链接]]` 的提及）** 与 **Unlinked mentions（出现笔记名但未链接）**；按笔记分组、组内列出提及。
- **上下文摘录**：默认截断显示提及所在片段，提供 **"Show more context" 开关**切换为显示提及所在的完整段落；支持折叠结果、切换排序、文本筛选框过滤提及。
- 展示位置三种：右栏面板；可锁定到指定笔记的反链标签页；以及 **"Backlinks in document"** 在笔记底部内嵌反链区。
- 官方文档未写明点击行为；社区通行行为是**点击后打开目标笔记并短暂高亮命中片段**。

**思源**（官方介绍 + 社区资料）：
- 反链按 **「引用」（显式块引用）与「提及」（文本提及）** 两组组织，默认按文档级列出；面板支持过滤搜索；点击引用项可**定位到当前文档中的定义块**。`Alt+B` 呼出。
- 原生面板的**上下文清晰度是公认短板**：社区专门做了「反链管家」插件做「渐进式展开反链上下文」；也有 issue（#12796）抱怨反链视图混杂文档级/块级反链、可读性差——说明「上下文展示 + 可分级展开」是真实痛点而非锦上添花。

**Logseq**（社区与 issue 资料佐证）：
- 页面底部 **Linked References** 按来源页分组，**块默认折叠，需逐个点击展开**才能看到引用所在块的完整上下文（Reddit 上有专门请求自动展开的讨论）。
- 点击块引用会进入**孤立的块视图**，顶部给面包屑回链到父块/父页；直接「跳到原页该块并高亮」的体验正是用户抱怨点（issue #4460）。

### 4.2 简知建议交互

- 反链面板 = 按来源笔记分组的列表，每条反链显示：**来源笔记标题 + 引用行上下文摘录（取包含 `[[目标]]` 的整段或前后 1–2 行，截断 ~140 字）+ 高亮命中词**；提供「展开更多上下文」开关（对齐 Obsidian）。
- **点击定位**：点击反链项 → 打开来源笔记 → 滚动到对应行 → 命中片段闪烁高亮（CSS keyframes 渐隐背景色，1–2s），对齐 Obsidian/思源的定位体验，避免 Logseq 的孤立块视图问题。
- **索引设计**：建 `backlinks(target_note_id, source_note_id, source_line/offset, excerpt, updated_at)` 索引表，保存笔记时同步重建该笔记作为「来源」的条目（解析 `[[ ]]` 时记录行号/偏移）；反向查询走 `target_note_id` 索引。excerpt 落库可让面板零成本渲染。
- Unlinked mentions（无链接提及）实现成本高（需全库文本检索去重），**放 v0.4**，v0.3 只做 Linked mentions。

## 五、对简知 v0.3 的落地建议汇总（每条一句话）

1. 层级树用邻接表（`parent_id` + 步长 10 的 `position`），不做 clone，选父笔记本时用 SQLite 递归 CTE 聚合子树笔记。
2. 删除含子树的父节点时禁止静默：提示后连带软删（或引导先移动子节点），不做「子节点上提」。
3. 拖拽用「前/内/后」三区判定（插入线 + 节点高亮），悬停折叠节点 300–500ms 自动展开，禁止拖入自身子树，并保留键盘移动方案。
4. 命令面板复用单一 Quick-Pick 式控件，动作用中心注册表（id/title/keywords/group/hotkey/run）注册，面板只做消费者。
5. 面板混合编排学 VS Code 前缀路由：默认混搜笔记+命令，`>` 只搜命令，`[[` 跳双链目标；空输入展示 MRU + 固定项。
6. 模糊匹配用带评分的子序列匹配（连续/词首/靠前/短名加分）并高亮命中字符，列表展示快捷键。
7. ZIP 导出目录学 Joplin：笔记本层级 = 文件夹层级 + 根级 `_resources/` 统一附件，导出前两阶段扫描以改写 `[[双链]]` 与图片链接为相对路径。
8. 手写 store ZIP：三段结构（local header / central directory / EOCD）字段精确写入，不用 data descriptor，先算 CRC32 再写头。
9. 中文文件名必须 UTF-8 写入并把 general purpose bit 11（0x0800）在 local header 与 central directory 同时置位，否则 Windows 解压乱码。
10. 显式写入以 `/` 结尾的目录条目以保留空文件夹并兼容老解压工具；路径分隔符一律 `/`。
11. 反链面板按来源笔记分组显示「上下文摘录 + 高亮」，提供展开更多上下文开关，点击打开来源笔记并滚动定位、闪烁高亮。
