## 一、HTML 粘贴转 Markdown（时机 + 范围 + 已知坑）

### 1.1 转换时机：默认自动转，快捷键逃逸
三家主流产品高度一致——**默认把剪贴板里的 `text/html` 自动转成 Markdown / 自家格式，而不是弹选择框**；用户想保留原样时用快捷键走纯文本：

| 产品 | 默认行为 | 逃逸方式 | 总开关 |
|---|---|---|---|
| Obsidian | 自 v0.10.1（2020-12）起粘贴 HTML **自动转 Markdown** | `Ctrl/Cmd+Shift+V` 粘贴不带格式（per-paste） | 设置 → 编辑器 → **"Auto convert HTML"**（Advanced 区），关闭后粘贴纯文本 |
| Typora | 剪贴板有 `text/html` 就取 HTML 转 Markdown，**没有 HTML 才落纯文本** | "Paste as Plain Text"（`Ctrl+Shift+V`） | 无需开启，内置默认 |
| Notion | 粘贴富文本**默认保留格式**转为 Notion 块 | `Ctrl+Shift+V`（Mac `⌥⌘⇧V`）或右键 "Paste as plain text" | **没有**全局默认切换项，只能每次绕过 |

补充细节：
- **Obsidian**：粘贴时按住 `Shift` 可选择粘贴落点；把 URL 粘贴到**选中文字**上会自动生成 `[选中文字](URL)` 链接（官方 Editing shortcuts 文档保留的行为，与浏览器一致）。
- **Notion 网页端**在粘贴富文本时会出现粘贴选择提示（保留原格式 / 粘贴为纯文本），桌面端则以右键菜单为主（社区资料，官方文档未系统描述）。
- **结论**：「自动转换 + `Ctrl+Shift+V` 逃逸 + 设置留总开关」是行业共识，简知照此设计不会反直觉。

### 1.2 转换范围：GFM 表格 / 代码块 / 图片的处理约定
- **表格**：转为 GFM 管道表格（`|` 分隔 + 第二行 `---`/`:---:` 对齐行）；不支持的特性（见 1.3）降级为文本。
- **代码块**：优先转 **fenced 代码块**（``` + 语言标注，来自 `<pre><code class="language-x">`）；无语言信息时至少保留围栏；turndown 核心不带 GFM 插件时会退化成**缩进代码块**。
- **图片**：转为 `![alt](url)` 外链并保留原 URL；Obsidian 对剪贴板里的**图片数据**（非 HTML 引用）另有行为：存为附件再插入 `![[Pasted image x.png]]`，与 HTML 引用是两条路径。
- **链接**：`<a href>` → `[text](url)`；纯 URL 文本一般保留为裸链接；锚点/相对链接转绝对链接是社区插件的增强点（如 Better Paste 顺带剥离 URL 追踪参数）。
- **其他**：任务列表 `<input type=checkbox>` → `- [ ] / - [x]`（GFM 插件 taskListItems）；删除线 `<del>/<s>` → `~~x~~`；未知内联标签默认按普通文本拼接。

### 1.3 turndown 及同类库的已知坑
turndown（`mixmark-io/turndown`）是 HTML→Markdown 的事实标准 JS 库，已知问题：
1. **核心不支持 GFM 表格**，必须挂 `turndown-plugin-gfm` 插件；原包已失修，建议用 Joplin 维护的 fork **`@joplin/turndown-plugin-gfm`**。
2. **复杂表格静默失败/降级**：colspan/rowspan、单元格内块级内容（嵌套列表、段落）转不出来（Joplin issue #9885 同类问题），且**不报错**——需要在转换前后检测 `<table>` 数量与产物表格数量做对账提示。
3. **嵌套列表里的代码块缩进易错**：4 空格缩进与列表项缩进叠加，fenced 块在列表内经常对不齐或被渲染器吃掉，常见解法是自定义 `turndown.addRule` 或对 DOM 先做预处理。
4. **转义污染**：turndown 用 `\` 转义 Markdown 特殊字符，网页正文里的 `*`、`_`、`[`、`~` 等会被大量反斜杠污染，粘贴观感差；简知应选**最小转义**策略（只转义真正有歧义的字符）。
5. **未知/噪音标签**：`<script>`/`<style>` 默认移除，但广告 `<div>`、隐藏元素等会留下空行或把文本挤在一起；**建议转换前先用 DOMPurify 清洗** + 手动白名单，再交给 turndown。
6. **性能**：大文档（Evernote 级 1MB+ HTML）转换慢（issue #265）；粘贴场景通常只是选区片段，问题不大，但不要对整页做实时转换。

## 二、多标签页（模型 + 关闭策略 + 快捷键）

### 2.1 标签与文件的模型
- **Obsidian**：标签是**视图实例**而非文件——**同一文件可以开多个标签**（这也是 pin 行为成立的前提：官方原文 "Links in a pinned tab always open in a separate tab."，即固定标签里的链接一律新开标签）。点击链接默认在**当前标签**打开；修饰键改变落点：`Ctrl/Cmd`=新标签、`Ctrl/Cmd+Alt`=新标签组、`Ctrl/Cmd+Alt+Shift`=新窗口。
- **VS Code**：编辑器组（Editor Group）模型，组内多标签；同一文件默认可在**不同组各开一个**（`workbench.editor.revealIfOpen` 默认 false），靠**预览模式**抑制泛滥——单击 Explorer 打开的标签是斜体的 preview tab，**复用**同一个预览标签，编辑或双击后才转正。
- **思源**：页签即文档视图；单击文档树在**当前页签**打开（覆盖式），`Ctrl+Click` 或右键"在新页签中打开"新开；同一文档可开多页签且**内容实时同步**；页签支持左右/上下分屏。

### 2.2 新建 / 关闭 / 重排 / 固定 / 拆分
- **新建**：Obsidian `Ctrl+T` 或标签栏加号；VS Code 双击标签栏空白处；思源右键"在新页签打开"。
- **拖拽重排**：Obsidian 拖动标签组内排序、跨组移动、拖出窗口变弹窗，拖拽时有 **drop zone 高亮**指示落点；VS Code 同样支持拖拽排序/跨组；思源支持页签拖拽与分屏拖放。
- **固定 pin**：Obsidian 右键 Pin/Unpin，核心效果是"链接强制新开标签"（防覆盖），侧边栏 pin 另有语义；VS Code pin 是"标签保持可见"（不因标签过多被挤掉）。两者共性：**pin ≠ 只读，而是防覆盖/防关闭**。
- **拆分 split**：Obsidian 右键 Split right / Split down（或把标签拖到另一个标签底部）；VS Code 拆分编辑器产生新组，`Ctrl+1/2/3` 跳组。
- **关闭**：Obsidian 官方 Tabs 页未明示关闭快捷键（惯例 `Ctrl+W`，恢复最近关闭 `Ctrl+Shift+T`）；VS Code `Ctrl+W` / `Ctrl+F4`，`Ctrl+K W` 关整组，`Ctrl+K Ctrl+W` 关全部。

### 2.3 关闭标签后的激活策略（关键分歧点）
- **VS Code 默认 = MRU（最近使用）**：`workbench.editor.focusRecentEditorAfterClose` 默认 true，关闭当前标签后激活**最近聚焦过**的标签（可能不相邻）；设为 false 才是浏览器式的**相邻激活**（优先右侧，无右侧则左侧）。
- **浏览器惯例**：关闭当前标签 → 激活右侧，无则左侧；`Ctrl+Tab` 按位置顺序循环。
- **Obsidian**：官方文档未明示激活策略，不做硬性论断；实际体感接近浏览器相邻激活。
- **建议**：个人知识库用户大多同时是浏览器/编辑器用户，**默认相邻激活（右→左）最不出错**，把 MRU 作为可选项。

### 2.4 快捷键约定（三家 + 浏览器高度收敛）
| 操作 | Obsidian | VS Code | 思源 | 浏览器惯例 |
|---|---|---|---|---|
| 新建标签 | `Ctrl+T` | —（由打开文件触发） | — | `Ctrl+T` |
| 关闭标签 | `Ctrl+W`（惯例） | `Ctrl+W` / `Ctrl+F4` | — | `Ctrl+W` |
| 恢复最近关闭 | `Ctrl+Shift+T` | — | — | `Ctrl+Shift+T` |
| 切换标签 | `Ctrl+Tab` / `Ctrl+Shift+Tab` | `Ctrl+Tab`（MRU 序） | `Ctrl+Shift+[` / `]` | `Ctrl+Tab` / `Ctrl+PgUp/PgDn` |
| 定位标签 | `Ctrl+1..8`，`Ctrl+9` 最后一个 | `Ctrl+1..9`（定位编辑器组） | `Ctrl+1..9` | `Ctrl+1..8`，`Ctrl+9` 最后一个 |

## 三、任务日期（emoji 约定 + 分组排序）

### 3.1 Obsidian Tasks 的日期 emoji 约定（事实标准）
- **精确格式**：`emoji + 空格 + YYYY-MM-DD`（含前导零），例如：

  ```markdown
  - [ ] take out the trash 🛫 2021-04-05 ⏳ 2021-04-08 📅 2021-04-09
  ```
- **三种日期**：
  - `📅` **due**：必须完成的最后期限（官方原文："the date it is due"）。
  - `⏳` **scheduled**：计划着手处理的日期（"you can schedule to finish a task before it is due"）。
  - `🛫` **start**：最早可开始的日期，可用来"到某天才显示任务"。
- **规则**：三种日期**顺序任意、可只用部分**，可放在任务行内任意位置；另有 `➕` created、`✅` done、`❌` cancelled、`🔁` 重复。
- **格式不可配置**：只认 `YYYY-MM-DD`，**不能**写成 `[[2024-09-17]]` 链接、**不能带时间**；`📅 today` 这类相对日期文本不被理解。
- **可见性规则**："Task is visible on the **latest** of its dates"——任务从 start/scheduled/due 中**最晚**的那个日期起才可见/激活。注意与 `happens` 区分：**`happens` = 三者中最早的一个**（用于过滤/分组的聚合字段），两个"最晚/最早"并不矛盾，一个是显示时机（保守），一个是聚合口径。
- **Overdue（逾期）**：以 **due 在今天之前且未完成**为口径；只有 scheduled 没有 due 时，社区惯例用 scheduled 兜底判逾期（官方查询常用 `(due before today) OR (scheduled before today)` 组合）。
- **无效日期静默忽略**：如 `📅 2021-04-32` 不会报错，但该任务在所有日期搜索中**静默找不到**（可用专门查询找出无效日期任务）——简知的解析器至少要在控制台/日志里记警告。

### 3.2 逾期 / 今天的视觉强调
- Tasks 5.x 把日期渲染为**带语义类名的 span**（`task-due`、`task-start`、`task-scheduled`、`task-created` 等）并在任务行上挂 `data-task-*` 属性，主题/CSS 据此定制；插件设置里还有内置样式开关（Short Mode、Urgency Score 等）。
- **社区主题的强调惯例**（Tasks 官方 discussion #1829 等）：**逾期 due 红色、今天 due 蓝色高亮**（如 `.task-due[data-task-due="today"] span { background:#d2e8fa; }`），未来日期淡化。
- 简知可直接采用：**Overdue 红 / Today 蓝 / Future 普通色**，渲染成带 `data-task-due="overdue|today|future"` 属性的元素，方便后续主题化。

### 3.3 按日期分组与排序的常见做法
- **`group by due`**：分组标题默认**从旧到新**（oldest first），加 `reverse` 反转。
- **无日期任务的归宿**：Tasks 分组头有五个固定分类——**Invalid date / Overdue / Today / Future / Undated**，"没有日期"排最后，保证任何任务都进组。
- **`group by happens`**：按 start/scheduled/due 的**最早**日期分组；需要按年月聚合时用 `group by function task.due.year + '-' + task.due.month` 这类表达式。
- **`show empty groups`**：显示空组（做日历感视图时有用）；`limit` / `limit groups` 限量防性能塌方。
- **组内排序**：`sort by due` 等默认**升序（最早在前）**，可加 `reverse`；常用组合是 `sort by due` + `sort by priority`（先按日期再按优先级稳定排序）。

## 四、代码块复制（交互细节）

### 4.1 位置与显现方式
- 主流文档站（VitePress——Vue 官方文档同款、Docusaurus——React 生态主流、react.dev）统一把复制按钮放在**代码块右上角**（与左上角语言标签相对）。
- 显现方式两种流派：**hover 才显现**（VitePress：悬停代码块时淡入，避免视觉噪音）与**常驻**（Docusaurus：始终可见，可发现性更好）。个人知识库内容密度高，hover 显现 + 移动端常驻（移动端无 hover，需直接显示）是稳妥组合。

### 4.2 成功反馈形式
- **不弹 toast**，反馈就地发生在按钮上：文案 `Copy` → `Copied!`，或图标"复制"→"对勾 ✓"（两者可叠加）。
- **1.5~2 秒自动恢复**：Docusaurus 官方 Gist 用 `textContent = 'Copied'; setTimeout(..., 2000)`；VitePress 内部同样硬编码约 2s。行业默认约 **2 秒**。
- **可配置面**：VitePress 提供 `themeConfig.copyCode.tooltips`（`copyCode`/`copied` 文案可本地化，见 issue #4431）；Docusaurus 无内置文案配置，需 swizzle `CopyButton` 组件。react.dev 也是右上角按钮、点击短暂变 "Copied"。
- **无障碍惯例**：按钮带 `aria-label="Copy"`，成功后同步更新（screen reader 可感知）。

### 4.3 工程注意点
- 用 `navigator.clipboard.writeText()`，**需要安全上下文**（https 或 localhost）——自部署 HTTP 环境要降级 `document.execCommand('copy')` + 隐藏 textarea 方案。
- 复制**不应移动焦点/光标**，粘贴后用户仍在原位置继续编辑。

**参考来源**：
- VitePress copyCode 配置与本地化：https://github.com/vuejs/vitepress/issues/4431
- Docusaurus 复制按钮官方示例（2s 恢复）：https://gist.github.com/yangshun/55db997ed0f8f4e6527571fc3bee4675

## 五、落地建议汇总（每条一句话）

1. 粘贴默认自动转 Markdown（读剪贴板 `text/html` 分支，turndown + `@joplin/turndown-plugin-gfm`），`Ctrl+Shift+V` 一律粘贴纯文本。
2. 设置里留 "自动转换 HTML" 总开关，行为与 Obsidian 完全对齐，不弹选择框打断输入流。
3. 转换前先用 DOMPurify 清洗 HTML（去 script/style/隐藏元素），粘贴后对账"表格数 vs 产物表格数"并在静默降级时提示。
4. 复杂表格（colspan/rowspan、单元格内块级内容）接受降级为文本，不做过度工程。
5. 嵌套列表内的代码块写自定义 turndown 规则或 DOM 预处理，转换后统一缩进，避免 4 空格灾难。
6. 转义策略选最小转义，防止网页正文里的 `*`、`_`、`[` 被反斜杠污染。
7. URL 粘贴到选中文字上自动生成 `[文字](url)`，与 Obsidian/浏览器一致。
8. 标签页允许同一文件多开（标签=视图实例）；Pin 标签内的链接强制新标签打开，防覆盖。
9. 关闭激活标签后默认激活相邻标签（优先右侧，浏览器直觉），MRU 作为可选项。
10. 快捷键照浏览器惯例：`Ctrl+T` 新建、`Ctrl+W` 关闭、`Ctrl+Shift+T` 恢复、`Ctrl+Tab`/`Ctrl+Shift+Tab` 切换、`Ctrl+1..9` 定位（9=最后）。
11. 点击链接默认当前标签打开，`Ctrl+Click` 新标签、拖拽重排带 drop zone 高亮、支持左右/上下分屏。
12. 任务日期采用 Tasks emoji 事实标准：`🛫 start` / `⏳ scheduled` / `📅 due` + 空格 + `YYYY-MM-DD`，顺序位置自由、格式不扩展（不带时间、不用链接）。
13. 任务可见性按"三者最晚日期起可见"，聚合/分组用 happens（最早），解析器对无效日期静默跳过并记日志。
14. 逾期红色、今天蓝色、未来普通色，日期渲染为带 `data-task-due="overdue|today|future"` 的 span 便于主题覆盖。
15. 任务列表按日期分组用 Invalid / Overdue / Today / Future / Undated 五段式，无日期排最后，默认从旧到新、组内再按优先级排序。
16. 代码块右上角放复制按钮（桌面 hover 显现、移动端常驻），点击后按钮变 "Copied/✓" 约 2 秒自动恢复，不弹 toast、不动焦点。
