# v0.9 定向调研：笔记模板 / 拼音首字母匹配 / 日期段排序

> 调研日期：2026-09-19
> 调研范围：Obsidian Templates 核心插件、SiYuan 思源模板片段、Notion 数据库模板；中文软件拼音/首字母检索惯例；任务日期段（Overdue/Today/Future/Undated）内排序惯例。以官方文档为准，社区资料为辅。

## 一、笔记模板（存放约定 + 变量 + 应用方式）

### 1. Obsidian Templates 核心插件

来源：[官方帮助 Templates](https://help.obsidian.md/Templates)（经重定向 obsidian.md/help/Templates 抓取）

- **存放约定**：设置项 **Template folder location（模板文件夹位置）** 指定库内一个文件夹存放模板；只有该文件夹内的文件才会出现在模板列表（不设置则全库 Markdown 均可选为模板）。模板本身是普通 `.md` 文件。
- **内置变量**：
  - `{{title}}` —— 当前笔记标题
  - `{{date}}` —— 当前日期，支持格式后缀 `{{date:YYYY-MM-DD}}`
  - `{{time}}` —— 当前时间，支持格式后缀 `{{time:HH:mm}}`
  - 日期/时间格式采用 **moment.js 格式语法**（YYYY 四位年、MM 两位月、DD 日、HH:mm 等）；插件设置中有「日期格式」「时间格式」两个全局默认格式项。
- **应用方式**：命令 **Templates: Insert template（插入模板）** → 弹出模板列表选择 → 内容（变量已替换为实际值）插入到**当前笔记的光标位置**。核心插件**只提供"插入到当前笔记"**，没有"新建笔记时选模板"（新建时套模板由 Daily notes 核心插件用日记模板，或社区 Templater 插件承担）。
- **替换时机**：变量仅在执行插入那一刻替换；直接编辑模板文件不触发替换（无动态绑定）。

### 2. SiYuan 思源 · 模板片段

来源：[官方下载页](https://b3log.org/siyuan/)（data/templates 目录约定）、[思源中文用户指南仓库](https://github.com/siyuan-note/user-guide-zh_CN)（已归档，.sy 笔记本格式）、社区模板仓库 [Achuan-2/siyuan-note-templates](https://github.com/Achuan-2/siyuan-note-templates)、教程 [思源笔记模板使用与语法（知乎）](https://zhuanlan.zhihu.com)

- **存放约定**：模板片段是工作空间 **`data/templates` 目录下的 `.md` 文件**，支持子文件夹分类；内置「文档导出为模板」功能，导出的模板默认存放在模板文件夹根目录。`data/templates` 与 `data/widgets`（挂件）、`data/plugins`（插件）并列为标准目录。
- **内置变量**：`{{title}}`（文档标题）、`{{date}}`、`{{time}}`，支持自定义格式后缀如 `{{date:20060102}}`。格式语法是 **Go 语言参考时间布局**（`2006-01-02 15:04:05`，即"1月2日下午3点4分5秒2006年"这一魔法参考时间的数字各表其位，如 06=两位年、15=24小时制）。
- **高级能力（对标参考）**：模板基于 **Go template + Sprig 函数库**，高级语法写作 `.action{ ... }`；可在模板内用 `queryBlocks` / `querySpans` 等函数执行 **SQL 查询**（`SELECT * FROM blocks WHERE ...`），在插入时一次性计算并把查询结果渲染为静态内容；可用当前文档标题（`.title`）等做查询传参，实现"一个模板多处复用"。注意：计算是一次性的，插入后不随后续数据变化更新。
- **应用方式（两种并存）**：① **新建文档时选择模板**（新建对话框里选）；② **插入模板到当前文档光标处**。另有笔记本级「日记模板」配置（每日笔记自动套用指定模板，对应配置项 dailyNoteTemplatePath）。

### 3. Notion · 数据库模板（New 旁下拉的 Template Button）

来源：[官方帮助 Database Templates](https://www.notion.com/help/database-templates)

- **存放约定**：模板**存放在数据库内部**——点数据库 **New 按钮旁的下拉箭头 → “+ New template”** 创建；模板标题即模板名。模板**只在创建它的那个数据库内可用**，不出现在其他数据库；数量无上限。与"文件系统固定文件夹"是两种截然不同的存放哲学。
- **应用时机**：**仅针对新建页面**——点 New 下拉菜单选某个模板生成新页面，或新建弹出菜单中选模板；官方文档未提供"把模板应用到已有条目"的能力。
- **变量/预填**：模板可**预设属性值**（如 Bug 模板自动把 Priority 设为 P1）；模板正文为静态内容复制（图片、子页面等）。页面正文层面**未提供 `{{date}}` 类动态日期变量**。⚠️ 注意 relation 属性预填会让每个新页面关联到同一个旧页面。
- **Repeating templates（重复模板）**：可让模板按日/周/月/年周期自动创建副本，可设间隔、开始日期与时间；嵌套最多三层，"每日循环"模板内不能再嵌套模板。

### 4. 三者对比（简知 v0.9 对标要点）

| 维度 | Obsidian Templates | SiYuan 模板片段 | Notion 数据库模板 |
|---|---|---|---|
| 模板存放 | 库内固定文件夹（设置项可配） | 工作空间 `data/templates/*.md`，可子目录 | 数据库内部，仅本库可用 |
| 变量体系 | `{{title}}` `{{date}}` `{{time}}` + moment.js 格式后缀 | 同名三变量 + Go 布局格式后缀；`.action{}` + SQL 查询 | 属性预填为主，无动态日期变量 |
| 应用时机 | 仅"插入当前笔记光标处" | **新建时选模板** 与 **插入光标处** 两种都有 | 仅"新建页面时选择" |
| 替换时机 | 插入时一次性替换 | 插入时一次性计算（含 SQL） | 新建时静态复制 |

## 二、拼音首字母匹配（全拼/首字母 + 多音字 + 性能）

### 1. 系统级惯例：拼音搜索是中文系统的"隐形标配"

- **Windows 开始菜单搜索**：历来支持输入全拼或**拼音首字母**检索中文应用（如输入 `wyyyy` 搜出"网易云音乐"）；Win11 中该能力时好时坏，微软设计总监已确认搜索的可预测性问题并承诺优化（[Microsoft Learn 问答](https://learn.microsoft.com)、[IT之家报道](https://www.ithome.com)）。
- **macOS Spotlight**：直接键入拼音乃至拼音首字母即可检索中文条目，长期稳定（[Apple 官方支持](https://support.apple.com/zh-cn/102320)）。
- **结论**：对中文用户，"不打切换输入法、直接敲字母搜中文"是被操作系统级教育的交互惯例，个人知识库应视为**默认预期**而非加分项。

### 2. 文件搜索工具：全拼 + 首字母双模式、多音字命中

- **Listary**：官方明确宣传"输入名字就能立即获取搜索结果，**支持拼音和拼音首字母**"，开箱即用（[listary.net](https://www.listary.net)、[help.listary.com](https://help.listary.com)）。
- **Everything**：原生不支持拼音，需要社区扩展 [IbEverythingExt](https://github.com/Chaoses-Ib/IbEverythingExt)（pinyin search），其规则最具参考价值：
  - **小写字母匹配拼音或原文**，**大写字母只匹配原文**（避免歧义）；
  - 支持**简拼（首字母）、全拼、带声调全拼、双拼**四种模式，默认开启简拼 + 全拼；
  - **支持多音字**（任一读音命中即可），并支持 Unicode 辅助平面汉字；
  - 提供 `;py` / `;en` 等后置修饰符显式限定"只按拼音 / 只按字母"匹配域。
- **FindX**（Everything 同款 MFT 接口的国产工具）：同样主打拼音全拼/首字母/混合与子串策略（[小众软件](https://meta.appinn.net)）。
- **共同惯例**：全拼与首字母**同时支持、无模式开关心智**；多音字**默认容错**；索引而非实时遍历。

### 3. 编辑器 / 笔记软件生态

- **VS Code**：原生 Quick Open（Ctrl+P）**不支持拼音匹配中文文件名**，只能按文件名实际字符模糊匹配；生态中也没有流行扩展解决此事（需自写扩展配合 [pinyin](https://github.com/zh-lx/pinyin-pro) 类库），长期是中文用户的痛点与空白点（[Quick Open 文档](https://code.visualstudio.com/docs/editor/userinterface#_quick-open)）。→ 说明"编辑器原生带拼音匹配"并非行业标配，而是中文工具的差异化能力。
- **Obsidian · Fuzzy Chinese Pinyin**（[lazyloong/obsidian-fuzzy-chinese](https://github.com/lazyloong/obsidian-fuzzy-chinese)）：对文件标题做拼音模糊搜索，可整体替换核心插件"快速切换"的快捷键；支持**全拼/双拼/模糊音**（双拼与模糊音不可同时开启）与**繁体**。→ 代表"文件快速切换"场景的拼音惯例。
- **Obsidian · Various Complements**（[tadashi-aikawa](https://tadashi-aikawa.github.io/obsidian-various-complements-plugin/)）：编辑时 IDE 式自动补全插件，内置**中文/拼音匹配**（输入拼音补全中文词，属输入补全而非文件检索），还支持韩语等。→ 代表"正文输入联想"场景。

### 4. 多音字容错与性能（实现参考：pinyin-pro）

来源：[zh-lx/pinyin-pro](https://github.com/zh-lx/pinyin-pro)（JS 生态事实标准）

- **多音字**：内置多音字智能识别（如"睡着了"→ shuì zháo le，"重庆"→ chóng qìng），**匹配时任一读音命中即算命中**；准确率宣称 99.846%。不需要用户参与消歧。
- **匹配 API（`match()`）**：输入串与文本匹配并返回**命中字符下标**（用于高亮），天然支持三种输入形态——**首字母**（`zwp` → 中文匹配）、**全拼**（`zhongwenpin`）、**全拼与首字母混合**（`zhongwp`）。这正是"全拼 + 首字母 + 混合输入"三合一的惯例实现。
- **性能基准（官方数据）**：5 千字约 5.958ms、1 万字约 15.26ms、100 万字约 820ms。→ **大库不能每次按键实时全量转换**，应当**预计算拼音索引并缓存**（标题/文件名变化时增量更新），检索时只在缓存的拼音串上做匹配；Everything（USN 索引 + Rust 的 ib-matcher）、Listary 亦均为索引式。

### 5. 本节结论（惯例清单）

1. 同时支持**全拼、首字母、混合连续输入**，不设模式切换。
2. **小写字母匹配拼音或原文，大写只匹配原文**。
3. **多音字默认容错**（任一读音命中），无需用户选择读音。
4. 拼音索引**预计算 + 缓存 + 增量更新**，检索路径零转换成本；模糊音/双拼属可选增强，个人知识库 v0.9 可不做。

## 三、日期段内排序惯例

### 1. Obsidian Tasks 插件（分组命名与简知完全同源）

来源：[Tasks User Guide · Grouping](https://publish.obsidian.md/tasks/Queries/Grouping) / [Custom Grouping](https://publish.obsidian.md/tasks/Scripting/Custom+Grouping)

- `task.due.category` 把任务分为 **Invalid date、Overdue、Today、Future、Undated** 五类，官方示例即先按 category 分为 **Overdue → Today → Future → Undated**，再按具体 due date 细分。
- **Undated 默认排在最后**（想要置顶需用 `group by function` 基于 groupNumber 自定义反转，属高级用法而非默认）。
- 日期细分组按**日期升序**展开（逾期段越久远越靠上，未来段越临近越靠上）。

### 2. Todoist（官方帮助《Default sorting order in Todoist》）

来源：[Default sorting order in Todoist](https://www.todoist.com/help/articles/default-sorting-order-in-todoist)

- **Today / Upcoming 视图默认 Smart sort 层级**：① 日期和时间（升序；任务无日期时用 deadline）→ ② 优先级（**P1→P4 降序**，即高优先级在前）→ ③ deadline → ④ 手动排序 → ⑤ 创建时间。
- **升序按日期排序时，无日期任务排在底部**；切降序才移到顶部。逾期任务不支持手动拖动。
- Filters 视图同理：含日期查询按 Smart sort，不含日期查询按 优先级 → 日期时间 → …。

### 3. 滴答清单（TickTick 中文版）

来源：[滴答清单用户手册 · 管理任务](https://xwzappest.gitbooks.io)、[官方帮助中心](https://help.dida365.com)

- 清单内提供六种排序：**自定义、到期时间、标题、优先级、指派人、清单**；「到期时间」即按日期升序。
- 「今天」智能视图的通行顺序：**过期任务在最前（按过期日期升序）→ 今天的任务**；分组 × 排序可自由组合（如时间分组 + 优先级排序）。

### 4. 本节结论（惯例清单）

1. 段间顺序固定：**Overdue → Today → Future → Undated**（Undated 默认最后）。
2. 段内按**到期日期升序**：Overdue 段越久远越靠上（欠得越久越先还）；Future 段越临近越靠上。
3. 同日内次级排序键为**优先级（高在前）**，再往前才轮到创建时间/手动排序。
4. **Undated 段默认放最后**，段内无日期可比，惯例按优先级（或创建/更新时间）排序；"置顶无日期段"只作为可配置项，不做默认。

## 四、落地建议汇总（每条一句话）

1. 简知的模板存入库内固定文件夹（如 `/templates`，可在设置中配置路径），对齐 Obsidian/SiYuan 的"文件夹约定"。
2. 模板变量只实现 `{{title}}`、`{{date}}`、`{{time}}` 三个基础变量，并支持 `{{date:YYYY-MM-DD}}` 格式后缀（用 dayjs 实现即可兼容 moment.js 常用写法）。
3. v0.9 先做"插入模板到当前笔记光标处"，"新建笔记时选模板"作为第二步（SiYuan 证明两种模式可共存）。
4. 变量在应用模板那一刻一次性替换，不做任何动态绑定或后续刷新（三家一致）。
5. 拼音搜索同时支持全拼、首字母与混合连续输入，不设模式开关。
6. 采用"小写字母匹配拼音或原文、大写只匹配原文"的大小写规则。
7. 多音字按"任一读音命中即可"容错，可直接复用 pinyin-pro 的多音字识别与 `match()`（返回下标便于高亮）。
8. 拼音索引对笔记标题/文件名**预计算并缓存**（如 SQLite 增加拼音列或内存 Map），变更时增量更新，检索时零转换；模糊音与双拼不进 v0.9。
9. 任务面板段间固定 Overdue → Today → Future → Undated，Undated 默认排最后（可留配置项但不做默认）。
10. 段内按到期日期升序、同日按优先级高在前、再按创建时间，Undated 段内按优先级（次选创建/更新时间）排序。
