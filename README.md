# 简知 JianZhi · 轻量级个人知识库

> 一个「调研驱动自研」的项目：先系统调研 9 个同类开源项目（`docs/research/`），对比功能/框架/技术选型/不足，再定方案（`docs/plan/`），最后动手实现并完整验证。v0.2~v1.1 按同一方法论迭代（见 `docs/plan/04~13`）。

**技术栈**：Node.js 22 + Express 5 + SQLite（better-sqlite3）｜ React 19 + Vite 8 + TypeScript（strict）

**零外部依赖**：不需要 Postgres、不需要 Redis、不需要 Docker——`node index.js` 一条命令即起，数据保存在本机单个 SQLite 文件里。

## 快速开始

```bash
# 1) 安装依赖（server + web + 根工具）
npm install && npm run setup

# 2) 构建前端（生产模式）
npm run build

# 3) 启动 → 打开 http://localhost:4321
npm start

# 可选：写入示例笔记（首启引导）
node app/server/scripts/seed.mjs
```

懒得敲命令：直接双击项目根目录的 **`简知.bat`** —— 它会检查依赖与构建产物、拉起服务、等端口就绪后自动打开浏览器。

> ⚠️ **不要直接双击 `app/web/index.html`**（或 `app/web/dist/index.html`）。它是前端源码入口，必须由 Vite 编译、由后端托管才能运行，用 `file://` 打开只会白屏。原因见下方「为什么不能双击 index.html」。

### 安装依赖时遇到 node-gyp / Visual Studio 报错？

个别机器上 `npm run setup` 会失败，报：

```
gyp ERR! find VS  Could not find any Visual Studio installation to use
npm error path .../node_modules/better-sqlite3
```

**这不是项目缺东西，而是一次多余的编译尝试**：`better-sqlite3` 官方包自带全平台预编译产物（包元数据为 `gypfile: false` 且没有 install 脚本，`prebuilds/` 内含 `win32-x64.node` 等），**本来不需要编译**；但部分 npm 版本仍会对它触发一次 `node-gyp rebuild`，而 Windows 上编译需要 Visual Studio Build Tools，于是中断。

绕过办法 —— 直接使用自带的预编译产物，功能完全一致：

```bash
npm install
npm --prefix app/server install --ignore-scripts
npm --prefix app/web install
```

验证是否正常：`npm test` 应输出 **86 项全部通过**。若坚持走编译路线，则需安装 Visual Studio Build Tools（体积数 GB，通常没必要）。

开发模式（前端热更新，/api 自动代理到 4321）：

```bash
npm run dev    # 同时起 server(:4321) 和 vite(:5173)，浏览器开 5173
```

测试与验证：

```bash
npm test                      # 后端集成测试（v0.1~v1.1 + 路径穿越回归，共 86 项）
cd app/web && npm run build   # 前端类型检查 + 生产构建
```

### 为什么不能双击 index.html？

`app/web/index.html` 是前端**源码入口**（引用 `/src/main.tsx`），要靠 Vite 编译后才能运行；`app/web/dist/index.html` 是**构建产物**，要靠后端服务托管。两者都无法用 `file://` 打开，原因有三层，任一层都是致命的：

1. **路径解析错位** —— 源码入口写的是根相对路径 `/src/main.tsx`，在 `file://` 下会解析到盘符根目录（`D:/src/main.tsx`），根本碰不到真实文件。
2. **浏览器禁止 `file://` 加载 ES 模块** —— `<script type="module">` 一律走 CORS，而 `file://` 页面的来源是 `null`、拿不到 CORS 头，Chrome/Edge/Firefox 直接拦截，React 无法启动。这一层连构建产物也一起否掉。
3. **前后端分离** —— 构建产物里有 47 处 `/api/*` 请求，需要 Express + SQLite 后端；脱离服务即使页面能加载也拿不到任何笔记。

因此双击时会看到一段明确的指引而不是白屏（源码入口与构建产物都做了这个兜底）。正确入口始终是 <http://localhost:4321>：`npm start`，或双击 `简知.bat`。

## 安全边界

- Markdown 渲染经 DOMPurify 消毒；SQL 全参数化；附件服务防路径穿越、非图片 MIME 强制下载 + nosniff；项目无任何硬编码凭据。
- **无鉴权**，仅限本机/可信内网使用；如需暴露公网，请套反代加 BasicAuth/IP 白名单。
- 路径穿越有四层防护：上传文件名经 `sanitizeFileName` 剥离分隔符、入库名恒带服务端生成的 `YYYYMM/<随机hex>-` 前缀、`/files/*` 与导出 ZIP 均 `resolve` 后校验仍位于附件根目录内、备份名走 `BACKUP_NAME_RE` 白名单。以上均由 `app/server/test/path-traversal.test.mjs` 以攻击者视角回归覆盖（含「附件根目录之外放金丝雀、强制孤儿清理后仍须完好」的越界删除断言）。
